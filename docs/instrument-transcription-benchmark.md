# 真实弦乐采音与音尾对照

这组实验补充《樱花草》的作者采音参考，用真实录音的音高起止标注检查持续音。它不评价制谱层数、LN 放手选择或手感，研究模型仍未默认接入应用。

## 数据与预先固定的选择

数据来自 Rochester AIR Lab 的 [URMP 项目](https://labsites.rochester.edu/air/projects/URMP.html)，使用 YourMT3 作者提供的 [16kHz 副本](https://zenodo.org/records/8021437)。压缩包为 `urmp_yourmt3_16k.tar.gz`，521421107 字节，提供方 MD5 `4f539c71678a77ba34f6dfca41072102`，本地 SHA256 `e6ac226c25a8cbc63f876a9314f87f16ada43b984da033474cf5754bb7e40819`。音频、逐音符标注和原包均在忽略目录 `test-data/urmp`。

在运行模型之前，固定选择上游 MT3 测试划分 `[1,2,12,13,24,25,31,38,39]` 中编号最小的两首，保留各自的所有独奏轨和原混音：Jupiter 的小提琴、大提琴及混音，Sonata 的两条小提琴及混音，共六个输入。每个输入评分前 30 秒，模型另看结尾后 2.1 秒的音频上下文。没有按模型成绩筛选歌曲、乐器或起止位置。

上游配置也把这一测试划分用于验证，因此这是有明确来源的额外声学对照，**不是对预训练模型完全未知的新测试集**。两首都是弦乐，不能代替管乐、人声、鼓、合成音或复杂流行混音的检验。

使用随录音提供的 `Notes_*.txt` 起止与频率标注，不使用未对齐的乐谱 MIDI。模型只读取音频，不接收标签、乐器名、人工 BPM、书签或声部参考。所有评分保持物理音频时钟，不扣 22.5ms 制谱提前量，也不吸附拍线。标注本身可能存在边界不确定性，所以同时报告两组容差：

- 标准：起音 50ms；音尾取 50ms 与参考音长的 20% 中较大者；音高必须同半音。
- 固定时钟：起音 40ms、音尾 80ms；音高必须同半音。JSON 为兼容历史仍叫 `strict`；短音的 80ms 比标准下限 50ms 更宽，不能称为所有音都更严格。

2026-11-09 修订：旧完整区间指标按音尾是否早于评分终点筛选预测，可能让错误长音逃出分母。修订后，起音和完整区间指标都保留前30秒起音的全部事件，无论预测音尾是否越过评分终点或可用音频终点。核验六个输入的全部参考音尾均可在32.1秒上下文内观察，不需要删除参考事件。跨界数量另报；若新案例的参考音尾不可观察，脚本要求增加推理上下文后评分。历史数值保留于 `instrument-transcription-benchmark.json`，当前结果为 `instrument-transcription-benchmark-v2.json`。

匹配是一对一最大匹配，重复预测算误检。错误乐器类别和错误鼓事件不会被按答案删除；精确乐器类别另算指标。此次只重算已保存预测，没有重新运行或调整模型。

## 对照方法

YourMT3 源码、权重和隔离环境与[《樱花草》研究](sakura-source-research.md)完全相同。现有检测对照使用相同音频范围、Basic Pitch 起音/持续激活、瞬态融合及音尾收回，不训练或调整阈值。现有检测不预测乐器类别，因此不为它虚构类别分数。

模型的音尾来源也重新核查：先用官方解码器从保存的 token 还原音符，要求与第一次输出逐项相同，再标记显式放音、分块强制截断和同音高重弹。不能把强制截断直接当作 LN 放手。

## 六个固定输入的结果

表中每格均为“现有检测 → YourMT3”。F1 衡量这批标注的一对一匹配，不能解释为软件整体的准确率。

|输入|标准起音 F1|标准完整区间 F1|固定40/80ms完整区间 F1|
|---|---:|---:|---:|
|Jupiter 小提琴|0.7692 → 0.9524|0.6154 → 0.9048|0.5962 → 0.8333|
|Jupiter 大提琴|0.3429 → 0.6977|0.0952 → 0.6512|0.0381 → 0.6512|
|Jupiter 混音|0.4870 → 0.7937|0.3109 → 0.7302|0.3005 → 0.6825|
|Sonata 第一小提琴|0.8346 → 0.9636|0.7087 → 0.9636|0.6929 → 0.9091|
|Sonata 第二小提琴|0.6667 → 0.9375|0.3441 → 0.9375|0.3226 → 0.9062|
|Sonata 混音|0.6544 → 0.9257|0.3779 → 0.8800|0.3410 → 0.7771|

改善覆盖这六个输入，但大提琴仍有明显漏音。Jupiter 混音进一步要求乐器类别一致时，起音 F1 从 0.7937 降到 0.6190；预测中出现了中提琴类别，而录音标签为小提琴和大提琴。这意味着“音高与时点接近”仍不等于正确声部归属。

六个 token 档案均重建出了完全一致的音符。Jupiter 混音的 68 个模型音符中有 10 个端点带强制分块截断记录；Sonata 混音 94 个中有 1 个，另有 2 个未明确归因的后处理端点。它们均未被删除来改善评分。

完整结果保存在 `instrument-transcription-benchmark-v2.json`。测试仅覆盖两首的前 30 秒，尚不是全曲或广泛曲风验收。合成重复和弦上的全漏检等既有反例仍保留，不能因这组真实弦乐结果将模型全局替换。

## 重现

先取得并核验上述压缩包，在 `test-data/urmp/source.json` 保留 Zenodo 文件元数据、校验和与下载来源。以下脚本只提取固定选择的音频和纯文本标注，不执行压缩包内代码：

```powershell
.venv\Scripts\python.exe scripts/prepare_instrument_benchmark.py
.venv\Scripts\python.exe scripts/probe_instrument_baseline.py
```

对 `test-data/urmp/benchmark/manifest.json` 的六个输入逐一运行已有的 `research_instrument_transcription.py`，固定 `--start-ms 0 --seconds 30 --context-seconds 2.1`，输出到 `benchmark/yourmt3/<name>`。然后运行：

```powershell
test-data\yourmt3\venv\Scripts\python.exe scripts/audit_instrument_releases.py --runs <六个完成的推理目录>
.venv\Scripts\python.exe scripts/evaluate_instrument_benchmark.py --output <新的报告路径>
```

来源哈希、模型身份、推理窗口和各项统计全部记录；公开报告不包含逐音符事件或音频。
