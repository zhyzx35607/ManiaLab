# Timing诊断与波形时钟修复

2026-11-17。修复了制谱提前量改变诊断窗口归属、诊断来源丢失，以及波形原始/制谱时钟切换导致对齐错误的问题。本阶段改善对音工具的可信度；没有更改BPM估计、自动Timing接受门槛、模型或已选音符。

## 已复现的问题

- 原音频12,010、12,100、12,200、12,300、12,400ms这5个起音，本来形成一个可疑的12–24秒窗口。制谱提前22.5ms后，第一个音被重分到前窗，两窗都不足5音，整个可疑诊断消失。负提前量也能触发相反方向的错分。
- 原分析的鼓轨不足窗口由混音补查；再次检查、重新拟合Offset或生成时只重算数值，丢失`fallback/evidence_source`，无法继续解释证据来源。
- 只有1个起音时返回0个可评估窗口，界面仍显示“0段可能错位”；修改BPM后，旧检查文字和原自动Timing结论仍可能显示为当前结论。
- 原音频Offset115ms、提前量22.5ms时显示谱面Offset93ms；只改BPM后再把提前量设0，未舍入锚点被93+22.5替换，Offset漂到116ms。
- 波形切换至原音频时钟后，点击同一物理起音作对齐，旧实现直接使用波形位置作为制谱时间，会额外移动约22.5ms；候选起止叠加和定位也没有完整转换。
- 手填小数Offset（如93.5ms）时，后端返回取整后的94ms，前端仍比对93.5ms并静默丢弃诊断；载入参考偏好后恢复手动拍线，也可能留下候选旧拍线的诊断。

## 实现与兼容

`grid_diagnostics`用`audio_start`决定原音频12秒窗口，用当前制谱时间计算拍线残差；没有该字段时仍按原`start`读取。窗口时段用于原音频试听定位，不随提前量改变。无序起音也不再因列表最后一个元素较早而漏掉后段。

共享`analysis_timing_diagnostics`供检查API、Offset拟合API和实际生成使用。它重新计算覆盖率、相位和可疑状态，仅继承原窗口明确存在的来源标签；旧分析没有标签则保持未知。返回完整时钟身份、窗口证据不足列表及`available/partial/insufficient`。`available`仅表示所有窗口有足够起音可计算，不表示Timing正确，也不赋予自动接受资格。

界面按完整时钟和请求序号接收诊断；改动参数、切换项目或改走再改回同一数值都会使旧请求过期。证据不足显示不能判断，并提供对应区间的试听入口。已保存的新候选可恢复自身诊断；旧候选仍可读取，提示重新检查。原分析结论明确标明原BPM、Offset和细分，避免冒充当前手动拍线的结论。

波形叠加、距拍线偏差、对齐和端点定位统一换算显示时钟；旧候选采用自身提前量，当前拍线采用当前提前量。切换波形时钟保留同一物理位置。BPM、细分和半速/倍速修改保留原Offset锚点；明确修改Offset才更新它。

检查与拟合前将手填小数Offset按后端相同规则取整，半整数取相邻偶数，明确更新输入并提示使用的拍线；不放宽时钟身份比较。参考偏好恢复草稿后重新核对诊断身份。
