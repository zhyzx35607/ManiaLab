# ManiaLab 0.1.0-alpha.6-dev.26

Windows x64 Extended profile 公开试用预发布说明（草稿；尚未从精确 tag 构建、验证或发布）。目标是提供 dev.25 的四种一键制谱预设及 Extended 声部和乐器能力，并加入以下改进。

## 变更

- 精简主要分析界面：批量入口与高级采音、Timing 设置收进折叠面板，让常用导入、分析、预设和生成操作更容易找到。
- 新增批量分析：一次选择 2–10 首音频，逐首导入为独立项目，最多同时处理 2 首；单曲失败与取消不会丢掉其它歌曲的结果。批次界面显示每首状态并可打开项目；导入阶段支持取消，任务轮询可从短暂请求失败中恢复。
- 新增“主声部：鼓、钢琴、人声、其他伴奏”方案。此方案使用六源 HTDemucs，输出四个指定声部；原有完整六声部模式仍可输出鼓、贝斯、人声、钢琴、吉他和其他伴奏。
- 增加纯键型预设，采用显式左右手/手指布局：6K `3+3`、7K `3+1+3`、8K `3+2+3`（可选 `4+4`）、9K `4+1+4`、10K `5+5`。本版只增加键型选择与定轨映射，不修改 LN 生成逻辑。
- 保留均衡起步、纯起音（不写 LN）、偏持续音和节奏清晰四种一键预设。
- 最大密度提升至 50 物件/秒。
- Extended 模型、worker 和 CPU 运行时范围以随包 `release-manifest.json` 为准；Mapperatorinator 权重仍由用户按需联网下载。

## 源码验证

本地完整 Python/API 回归通过：`D:\project\ManiaLab\.venv\Scripts\python.exe -m pytest -q`，结果为 **3659 passed, 164 skipped, 1 warning**（420.25 秒）。唯一 warning 是短 STFT 边界测试中 SciPy 对 768 点输入缩短 `nperseg` 的提示。Edge Playwright 全套 `npm run test:ui` 为 **81 passed**（3.1 分钟），包括最多十首批量导入、并行数上限为 2，以及切换 8K 键型后阻止导出旧候选的浏览器回归。配置、推荐、LN、候选编辑、导入路由与上游路由定向组为 **129 passed**；`node --check` 和 `git diff --check` 通过。Windows PR CI 尚待推送后运行。

## Extended 包验证

本版 Extended 便携包必须从精确 dev.26 tag 源码构建，并验证随包 manifest、ZIP 结构和该 EXE 的能力。当前专用 D 盘 staging 中的旧音频 worker manifest 仍只声明 `four,six`，而 dev.26 要求 `four,six,four-piano`；需要先备份旧 worker，再由本版源码重建并绑定新的 worker manifest。此节只记录绑定到本版实际 Extended EXE 的检查；Core Windows workflow 的结果不代替 Extended 验证。构建、便携运行、collector 与 GitHub Release 仍待完成。

六声部真实歌曲问题当前没有可复现样例，不能据本版声称已修复。真实吉他、Tsumugi bass/other 音频专项所需的冻结测试输入已随 `test-data` 清理，不会复用旧 EXE 的便携验证报告。合成烟测仅证明组件可加载、执行和身份匹配，不证明真实歌曲采音质量、Timing 或游戏手感。真实歌曲、osu! 试打及 6–10K/LN 手感仍由用户下载后实际体验。
