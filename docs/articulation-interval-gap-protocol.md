# 连续起音表达中的区间空隙

2026-11-11，固定完整重放前记录。前一版按30ms起音组和起音间距判断节奏组，
在整个节奏组内统计拖尾比例，决定内部音是否都表达为短键。即使前半段音符
已经结束，后半段的密集拖尾也可能让前半段失去持续表达。两个最小反例在
旧实现中实际失败，修复前14项负例通过。

本轮只增加一种断开条件：同一来源内，已有候选区间均已结束至少80ms，且
当前起音上下文未出现未知音尾或非音高事件。80ms沿用原拖尾判别的时间尺度，
完整重放后不按结果调整。跟踪全部更早音符的最晚结束时间，不能忽略先前
节奏组中仍持续的音，也不以和弦音尾中位数充当全部声音结束。

未知音尾仍阻止新增断点，直到原有起音间距规则另起上下文；更早的原始音尾
仍参与最晚结束时间。原有起音间距规则本身不变。这是检测区间的空隙，
不是音频静音、物理松键或独立旋律身份的证明。新断点在trace中记为
`observed_interval_gap`，不会生成新起音、拼接候选或延长音尾。

第一轮检查已观察到《樱花草》原候选存在最长77834ms的钢琴起音组，但有
大量`reattack`未知尾；新保护条件尚未改变表达。不能因为希望更多LN就把
这些尾端改成已观测，或宣称本轮解决了该曲的连续性问题。

完整验证固定如下：

- 旧策略从PR #8保存的源码快照加载，先逐项复现当前基线候选、选择及定轨。
  原输入、PR #8报告、执行计划和逐事件产物均核哈希。
- 同一《樱花草》候选与13段方案、74 BPM、Offset178、四细分、22.5ms提前量，
  重放6–10K取舍、定轨、导出回读；同时报告各声部丢失/新增起音及LN。
- 使用原固定11份SMD钢琴的已保存激活解码，不重跑网络；核对原存档起止，
  保留全部采音，只比较表达变化。不读取MIDI标签或用户参考谱打分。
- 所有保留起音、音高、来源不变，音尾只能为原值或短键。段落切分不制造
  假尾，手动持续音和其他表达模式仍优先。工程通过不等于音乐验收。

本轮没有模型训练、分离改动或自动Timing改动，也不复用此前被否决的音高
连续激活拼接方案。新成果按独立PR保存；长期质量目标仍未达到。

## 完整v2后、v3重放前的修订

v2完整完成五键数和11份SMD，报告保留在
`test-data/articulation-interval-gaps-v2`。SMD Beethoven的9个原持续音因分组
变短、局部拖尾比例提高而被新短键化，117条持续表达变为108；其余10份及
《樱花草》均无变化。新分组不应为了保护前一段而压短原来保留的音。

因此v3只细分**旧规则已经判为连续敲击**的音组。旧规则保留的音组完整沿用，
并新增“不能把原LN变tap”的验证。一个简化反例在v2实际失败，修订后通过。
没有改变80ms或其他阈值，没有读取作者音符标签；v2结果不删除。

SMD使用全部70秒原输入的解码事件提供上下文，仅在原评分窗0–60秒统计
表达变化；不截掉右侧10秒后再假设已经观察。这里的计数不是MIDI匹配分数。
