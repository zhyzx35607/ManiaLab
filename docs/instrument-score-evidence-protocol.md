# 原采音模型的乐器评分验证

2026-11-11。先固定以下规则，再运行模型、读取本阶段逐音参考。
这是研究入口，应用默认行为不变，不训练新模型，不生成新谱面。

## 要回答的问题

Tsumugi `other_v1_5` 的区间分类头返回36类 logits，但旧转录只保存完整
排名，候选 `strength=1.0` 是统一权重。先恢复原分类评分，检查类别分歧
能否被识别，再决定它是否值得用于声部规划。分类评分不代表音存在概率、
力度、声部重要性或独立演奏者身份。

## 固定输入和恢复

- 原35份 URMP 对照：28独奏、7混奏；最多40秒输入，0–30秒计分。
  原报告 SHA256 `ff98a2e3c53671c1bcf4ec16a6c3cdff3215e17e239101dfe6883f884fbe2e75`；
  manifest SHA256 `e363a4e7b5f25628909eb13031251847492d9fa816e520b98fbc6d612bcda16a`。
- 复用保存的5202个原解码区间、315个窗口；不重跑 semi-CRF，不修改音高、
  起止、slot或拼接结果。区间由 `pair_id % 88` 和原 `v1_slot_index` 还原
  pitch-slot track。缺失slot或被拒绝的construction必须报错，不猜。
- 固定上游 `eba1c7d05e4d6a53cc4e8916d742d9623a3fdc38` 和原权重SHA
  `e836d5b30a29ad2301726aedb9ae348db927fbb4813359cdfb2e304ba3084501`。
  不修改上游。复核原音频、原PCM及重采样PCM、模型配置和载入完整性。
- CPU FP32、算子2线程/跨算子1线程、seed42、batch1，原8秒窗/4秒步进。
  每窗一次原模型前向，再调用原区间分类头和边界头。
- 保存原logits、区间索引、分类排名及边界响应。分类排名必须逐项复现原
  36类顺序；边界两个布尔值精确相同，分数绝对误差不得超过1e-6，并报告
  实际最大差。不同即停止，不用新结果覆盖旧音符。
- 用既有 `audit_tsumugi_releases.audit_replay` 核对官方拼接和原最终notes，
  保存construction→最终note的来源。原来源被合并、过滤的情况保留。
  先验证第一份12-1-vn，成功后在同一进程继续其余34份。推理串行且只载入
  一次模型；全部完成后才开始本阶段逐音标签评价。

## 预先固定的诊断和比较

- 基线：最终note继承的第一个来源的类别及评分，核对完整排名等于原note。
- 唯一比较：对该最终note的全部construction来源取等权logit均值，FP64累加。
  精确同分时优先原类别，否则最低class ID。不给较长的未决音尾更高权重。
  不搜索权重、阈值、温度或聚类参数。重叠窗相关，不把它们当独立投票。
- 两种方案记录最大sigmoid值、第一与第二logit差、sigmoid≥0.5的类别数、
  来源类别是否一致。sigmoid为模型响应，不称校准后的置信度。
- 固定分箱：最大sigmoid `[0,.5)、[.5,.8)、[.8,.95)、[.95,1]`；
  logit差 `[0,1)、[1,2)、[2,4)、[4,+∞)`。不因结果重新划界。
- 所有原预测保留，原 `is_drum` 不改，分别算50ms起音/同音高、完整区间、
  带广义类别两项，以及原40/80ms协议。跨30秒的尾仍入分母。
- 分箱诊断使用50ms且同音高的**双向唯一**对应，分别列类别正确/错误、
  无对应和歧义预测、原鼓预测；所有分箱合计必须覆盖全部计分预测。
  不用类别解开同音重叠，不把无对应统一叫确认的假音。
- 独奏/混奏分开汇总，另列每类乐器，不把同演奏复用当35首独立歌曲。

## 判定边界

本批只覆盖strings/sax/brass三类真值，不能证明能分清两把小提琴、合成器
或人声；公开数据可能与模型训练重合。均值类别F1改善也不能直接开启声部
选择。高分错类、漏采和边界错误仍要明确呈现；没有原声音乐验收就不宣称
采音或LN改善。该阶段先保存可复用证据和结论，再单独决定下一步。
