# 分窗起音证据保留协议

2026-11-10，在本轮保存输出重放前固定。这是发现Ravel起音被重叠替换、Skryabin起音被不完整音尾过滤后的开发修复，不能称独立盲测；原Transkun控制与实曲结果保持不变。

目标是分开保存“窗口识别了起音”和“已经得到可用音尾”，避免为了生成完整MIDI音符而丢掉有效起音。只重放既有91控制+12实曲的已保存原窗口，不执行新的神经网络推理，不训练、不融合Kong预测、不读人工时间来决定保留。

1. 保留官方最终全部钢琴候选及原起止时间，作为主列表。负音高踏板独立保留。
2. 每个窗把带 `has_onset=True` 的钢琴事件转换到未夹取的原始物理时钟。负时钟/超过输入范围的提案仍记录并标记，不夹成零时刻假起音。
3. 同音高按窗口顺序，一对一最大匹配至已有候选；去重容差固定为模型一个特征hop `1024/44100` 秒，按最小总起音误差选匹配。容差来自模型时间网格，不根据本轮参考标签调节。同窗两次起音不合并；跨窗以候选固定锚点匹配，不作链式漂移。
4. 未匹配提案作为新起音候选保留，携带原窗ID、原始起止、完整性标志；不把后续没有音尾的起音删除。它们是待核查证据，不是已经确认的正确音符。即使更早窗口提供的音尾被后续起音覆盖，也保存原始证据。
5. 起音候选与LN许可分离。每个候选保留各窗的音尾估计，但该脚本一律不授予自动LN放手资格；不沿用官方强制 `hasOffset=True` 作为放音确认。候选原估计区间仅用于显示，不以它评分音尾、截断/延长到参考谱或量化拍线。

对所有103输入完整重放，按原控制±100ms及实曲50/40ms协议评分起音，报告新增找回与新增未匹配预测的实际数量和逐曲变化；Nova仍仅比较作者起音组与层数，不把人工省略判为假音。保存全部候选/来源和输入/代码hash。最低继续条件是找回两处已定位的丢音、声源控制不引入新误采，且11段实录未匹配预测不增加；即使满足也只支持后续实曲验证，不直接启用应用。

结构测试覆盖跨窗同音重复、一窗内重弹、不完整音尾、负时钟/尾部越界、最大匹配贪心陷阱和不可变输入。测试只核查实现，不当音乐收益。主线程负责实现及运行，唯一子代理独立复算并检查重复提案的误认风险。
