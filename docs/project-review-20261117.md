# 2026-11-17 项目检查与结构优化

本轮把制谱编排从 HTTP 路由中拆出，统一音频与制谱时钟、资源打包和组件状态，并修复导入、导出及候选操作中的实际问题。它改善工程可靠性；真实音频采音、声部主次与 LN 音乐性仍是项目的主要未完成目标。

## 已处理的问题

| 问题 | 处理结果 | 主要验证 |
| --- | --- | --- |
| 制谱提前量或量化使音符跨过段落边界，套用错误偏好 | `audio_start` 保留原起点；声部策略按原音频查询，持续占轨按制谱时间查询 | 正负提前量、零点裁剪、量化合排与 API 导出回归 |
| 前段 LN 量化至下一段后可覆盖更紧的容量限制 | 同时约束音符所属段与当前制谱时间的占轨上限 | 5990→6000ms、下一段 `max_held=1` 回归 |
| 同次上传的文件与压缩包可静默覆盖同名资源 | 写入前统一检测大小写重名、目录与文件冲突 | 多输入、嵌套目录及失败清理回归 |
| 嵌套原谱配根目录补传音频时，导出引用失效 | `.osz` 在谱面实际引用位置包含音频 | ZIP 相对引用与严格保时检查 |
| 失败分轨上传残留文件，异常栈未进入所提示的日志 | 完整预校验；仅清理本次失败资源；持久日志带项目/任务标识 | 失败、取消和已有成功资源保护回归 |
| 本机旧钢琴模型被显示为可用，实际推理身份不符 | 状态按大小/SHA 核验；支持新旧模型共存；推理前强制验证 | 错误身份、缓存失效、当前版本路径与构建校验 |
| 构建能力取决于本地碰巧存在的文件，说明与实际包不一致 | `standard`/`extended` 显式范围；manifest、资源和使用说明共享声明 | 构建夹具、实际 EXE 状态对照 |
| worker 目录整树复制会夹带额外文件 | 构建时保存完整文件身份，暂存逐项复制并复验；拒绝额外文件和链接 | 私有文件、复制期间新增、依赖改变与旧验证报告回归 |
| 改变目标键数后仍可导出或编辑旧键数候选 | 显示目标与候选键数差异，阻止误用，重新生成后恢复 | Chromium/Edge 真实浏览器流程 |
| README 混入大量历史实验，常规 CI 缺浏览器操作 | 归档历史导航，新增架构/开发入口与隔离浏览器夹具 | 本地链接、语法及 CI 验证 |

早先审查对“预览使用目标键数绘图”的判断不准确：现有绘图已使用候选键数。本轮修复的是候选状态提示及导出/编辑保护，不把原本正确的绘图计为新增修复。

可选 Mapperatorinator 运行器也已统一 CPU 算子 2 线程、跨算子 1 线程。没有修改正在运行的研究脚本或重新执行旧歌曲模型队列。

## 结构与兼容

- `manialab/server.py` 保留请求校验、任务提交和存储边界；`generation.py` 负责制谱流程。
- `preferences.py` 明确原音频与制谱时间的查询语义；历史项目没有 `audio_start` 仍可读取，重新生成时得到该字段。
- `model_identity.py` 集中处理钢琴身份与状态缓存；`scripts/package_assets.py` 和 `worker_inventory.py` 管理发布输入。
- `tests/browser/` 使用独立临时项目与合成检测结果，不依赖私人音频；原有研究脚本、协议、冻结输入路径保持可追溯。

旧钢琴模型和历史研究产物保留；当前钢琴版本文件单独存放。旧 worker 若没有完整文件清单，不满足新包构建条件，应重建并重新核验，而不能补写清单把旧目录认定为已验证。`extended` 的新契约尚未经过整包实跑，本轮完整构建范围为 `standard`。

## 后续研究优先级

1. **Timing**：复用冻结起音，分开记录原始起音偏差、局部漂移和半速/倍速歧义；当前《樱花草》74/148/296 BPM 仍有重叠支持。`off_grid=0` 不作为正确采音的证据。见[诊断结果](sakura-timing-ambiguity-results.md)。
2. **声部取舍**：建立冻结多曲候选的可重复比较，检查重要声部的省略区间及原因。固定类别权重还不能等同于自动识别音乐主次；先定位失败段落，再单独评估规则修改。见[取舍审计](expression-tradeoff-audit-results.md)。
3. **LN 表达**：分别追踪物理音尾、踏板延音、乐句覆盖和实际放键，报告增加表达时带来的占轨及短键退步。见[固定候选重放](expression-current-replay.md)。
4. **最终体验**：保留原声听检与 osu! 试打验收；自动开发可先用冻结证据推进，不依赖逐首人工标签才能继续。

历史实验的候选数量、匹配率和本轮测试数量均不代表已经达到上述音乐目标。模型分发的已知许可状态继续以 [第三方声明](../THIRD_PARTY_NOTICES.md) 为准。

后续已落地[冻结多曲生成回归](frozen-generation-regression-results.md)：修复未来段落容量使整组消失、旧路径漏掉持条上限的问题；66例对照完整保存，并披露压力配置中人声/鼓点的取舍变化。
