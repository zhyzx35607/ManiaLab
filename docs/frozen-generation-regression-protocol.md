# 冻结分析的生成回归协议

2026-11-17。本阶段复用已有检测，核查生成软件在分段容量变化时的行为；不重新采音，不把作者谱当物理真值，不以保留物件更多作为音乐质量改善。

## 输入与控制

使用本地 `audio-choice-pairs` 中10个已有开发片段，覆盖原始6–10K各两首。这些数据已用于开发，不是独立泛化集；各片段约47–60秒，完整保留其边缘候选并记录原剪辑元数据。只读冻结 `deep/analysis.json`，不读取音频、原谱或保留测试。

- 默认配置：原键数及6K/10K去重后共26例；计划为 ignored `test-data/frozen-generation-plan-20261117/plan.json`，SHA `0696d759598b57ceaaefe3eb52ca3e78f0d443cee60c0816c4cda2d733fad593`。
- 分段配置：原键数下三种本地推荐，加一组沿既有结构段交替 `max_held=5/1` 的显式压力配置，共40例。推荐及参数在改生产代码前一次冻结，不因结果调节；计划为同目录 `section-plan.json`，SHA `bdcc88e9d1e9d56679f9f69b116a16f82a53099318663bf661420d4fef3c5a8b`。
- 时钟沿用已有检测 BPM/细分，Offset 按22.5ms制谱提前量换算。自动量化门槛独立记录；诊断生成显式确认该冻结时钟，不表示时钟已通过音乐验收。
- 运行 `scripts/replay_frozen_generation.py`，直接调用当前 `generate_variant`，包括表达、量化、选音、定轨、校验和 `.osu` 导出回读。全程串行，CPU 数值库线程上限2；不启动神经模型。

## 记录与判断

每例保留完整候选、逐ID变化和导出谱面于新的ignored目录，旧目录存在时拒绝覆盖。计划校验每个输入SHA；运行前后核对源码、计划与分析身份。对照要求计划字节完全相同，并校验旧候选哈希。

分开记录：自动Timing门槛、起音移动超过30ms、声部/段落保留和省略原因、LN数量及覆盖并集、缺失音尾来源、已明确不支持的音尾、结构与网格、实际持条/列占用。未知音尾来源不冒称已验证；旧数据的证据局限保留在结果中。

独立输出容量检查包含段落边界上的持续占轨，即使那里没有新起音。生成器的密度契约是在可选候选起音时检查 `(t-1000,t]`，包括后来省略的候选；独立报告只复核最终输出起音，不重建被省略候选时刻及其更紧的原音频段偏好，不能当作完整求解矩阵的独立证明。生产求解器另直接验证约束矩阵。非起音事件的滚动密度另记观察项，不在本阶段升级成更强规则。和弦容量只约束同一排起音。

对照记录基线报告SHA及其源码身份，另保存Python/NumPy/SciPy版本和数值线程环境。比较区分新增/删除ID、起止变化、仅换轨及同ID证据字段变化；生成时长和测试数量不代替音乐评价。

本阶段已复现的目标问题：最轻音组自身可行检查漏过未来低持条边界或其他声部候选时刻，导致本可保留部分完整起音/LN的组被全丢弃；旧无结构路径漏掉未来持条容量边界而超限。修复应保留既有音尾，不裁短LN来绕过限制；无结构路径继续保留选中的起音。

## 运行

```powershell
$env:OMP_NUM_THREADS='2'
$env:MKL_NUM_THREADS='2'
$env:OPENBLAS_NUM_THREADS='2'
.venv/Scripts/python.exe scripts/replay_frozen_generation.py --plan <冻结计划.json> --output <新的基线目录>
.venv/Scripts/python.exe scripts/replay_frozen_generation.py --plan <同一计划.json> --output <新的对照目录> --baseline <基线目录>
```

成功只证明本次数据和配置的生成契约。不能把合成边界修复、整齐网格、增加LN或测试通过称为真实声音识别、音乐表达或手感完成。
