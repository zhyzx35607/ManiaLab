# 试听PCM曾被研究路径误作原幅度音频

2026-11-09。复查ADT的重复事件时，发现若干旧声部研究直接读取`bundled/<voice>/preview.wav`。此文件由`manialab.audio.decode`把浮点音频截断至[-1,1]后写成int16用于试听。原始MP3解码可能超过满幅，因此它不等价于原幅度波形。

逐字节核验原MP3，再重新解码浮点PCM，全部声轨长度6258672样本、22050Hz。旧试听文件均能由同一浮点结果经过已知截断/量化逐采样完全重现：

|来源|原浮点峰值|超过满幅的样本占比|
|---|---:|---:|
|混音|1.5170|2.6872%|
|鼓|1.3856|0.5025%|
|人声|1.3906|0.0840%|
|其他|1.1851|0.00125%|
|钢琴|0.9806|0|
|贝斯|0.6026|0|
|吉他|0.001234|0|

这说明此前鼓频谱与转录研究存在输入失真，不能继续称它是未经改变的原幅度PCM。截断是否解释分类或解码失败尚需同条件对照，不能仅凭发现问题宣称质量改善。钢琴没有满幅截断，但仍有int16量化。旧报告、模型和样本不改写。

应用分析的`decode`返回的是截断前的浮点数组；本次发现直接涉及把试听文件作为推理输入的研究脚本，不据此虚构应用所有采音都被截断。已有多曲四声部实验读取原NPY，本问题不推翻其记录。

新增`prepare_sakura_pcm.py`从核验过的原始音源生成独立float32 WAV，记录来源与解码器身份，并可逐样本核对已有产物。新研究可读取该目录；旧结果的音频哈希与范围仍保持原样。独立对照结果未出之前，不自动用新输入替换旧缓存。

后续同方法float线性分类对照已完成：后段kick/snare分数均与旧int16相同；第4列F1从0.3814降到0.3502，未显示修正削波本身能解决选音。ADT已知循环块也分别用int16、原float、逐块峰值归一化float运行64-token诊断，三种输入均在第4块重复事件且没有EOS，第5块均正常结束。两项结果都不支持“削波是全部失败原因”。更换输入格式是保证研究证据可靠的修正，不是已获得质量收益的结论。

## 应用分离入口的独立复查与修复

随后检查正式 `Separator.separate()`，另发现其向四/六声部 worker 提供的 44.1kHz 双声道 WAV 使用 `pcm_s16le`。这与前述研究误用试听文件是两条不同路径；`audio.decode` 与用户导入声轨保存的 NPY 仍保留原浮点幅度。

实际运行相同 FFmpeg 命令，包含峰值 1.5、−1.25 和微弱采样的测试输入经 int16 后最大误差 0.5000305，改成 `pcm_f32le` 后逐采样误差为 0，起点与长度相同。《樱花草》原混音在本入口解码为 12517344 帧双声道，峰值 1.11494，343 个声道采样超满幅，占比 0.0013701%；旧 int16 最大误差 0.1149712。这里的双声道数据不能与上表单声道解码的幅度、削波比例混用。

现在输入保留 float32，分离缓存增加输入处理身份；音高激活缓存同时记录包含处理身份的分离签名，并升级为版本 3。旧分离结果不能因音源和权重相同而被误复用，重新分离也不能继续读取旧音高激活。用户导入声轨按自身内容身份复用，不受分离模型处理版本变化影响。

检查包括真实 FFmpeg 转换、四/六声部旧缓存失效、当前缓存复用、仅补节拍分析、下游音高缓存刷新，以及导入超满幅声轨的原幅度保留。现有打包 worker 分别实际读入了 float32；另用《樱花草》6.664–18.664 秒运行完整应用六声部分离与节拍流程，六轨均为 264600 个有限采样，第二次调用复用了新缓存。全量 320 项测试通过。这些只证明数据传递和运行兼容性，未证明采音、分离听感或 LN 质量达标。

本地证据位于 `test-data/separation-input-audit-v1`，包含转换前后文件、数值报告和实际应用流程元数据；原音频不公开。
