# 下一阶段：6–10K / LN 专项训练

当前工作台先解决可检查、可比较、可导出的闭环。没有合适的训练语料和验证集时，不把启发式编排称作“10K 专训”。

## 数据先行

1. 收集有音频配对的原生 6–10K 谱面，按键数、谱师、歌曲、LN 持续时间、同时占轨数、短键与 LN 混合方式分层统计。
2. 原创 LN、Inverse、转换图分别标记。LN 多不等于音乐表达好；不把 Inverse 补空间结构误当成持续音标注。
3. 先用 `audit_corpus.py` 检查同轨重叠、无效 LN、重复谱和缺音频。按音频内容哈希划分 train / validation / test；同音频不同难度必须进入相同集合。不同编码的同曲音频还需要指纹归并，脚本目前不能自动完成这一步。
4. 用户自己的图可作为风格参考和回归样本，但不能作为唯一质量标准。没有人工风格标记和试听审核的图不直接作为金标准。

## 两个学习任务

**音乐物件选择**：给定音频证据、段落上下文和难度，预测哪些起音值得表达、哪些持续区间应形成 LN、何时收尾。需要区分物理音尾、混响和编排意义上的收尾，也允许通过完整旋律声部建模表达跨音高持续长条。

**保时键型编排**：给定固定的物件起止对和键数，在完整 LN 占轨状态下分配轨道。训练不能拆散 LN 起止配对，必须保留跨窗口仍在按住的轨道状态。6K 到 10K 不应只通过简单缩放列号迁移。

原项目 V32 mania 权重可作为生成基座。要独立验证数据筛选、键数采样权重、LN 时长分布、起止配对表示和跨窗口状态后再选全量微调或 LoRA；不能只提高 `hold_note_ratio`。原仓库默认 LoRA 配置指向 standard，必须改为 mania 并使用对应权重和数据。

## 可测的验收

- 音频层：人工标注片段上的起音 / 音尾误差、持续音漏检、混响误检；不同乐器与混音复杂度分别统计。
- 表达层：长 LN 的持续依据、段落一致性、释放节奏、LN 与短键配合；使用对照试听和玩家盲评，而不是单独追求 LN 比例。
- 定轨层：重叠必须为零；统计短放键间隔、连续同轨、每只手占轨负担、反复键型和跨小节连贯性。结构指标不能代替手感评价。
- 迁移层：10K 独立验证，并分开报告 6/7/8/9K，避免大量 4K/7K 训练数据掩盖 10K 退化。
- 对照：原版 Mapperatorinator、当前证据编排基线、专项训练版本，同歌同难度比较。保留完整失败样例。

现阶段优先用工作台积累“原始音频—采音候选—生成结果—人工修改—偏好选择”的本地样例。这比先堆更多参数更能帮助判断下一步该训练什么。
