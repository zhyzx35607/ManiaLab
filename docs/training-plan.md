# 6–10K / LN 训练：已完成与下一步

alpha.4 已包含一个实际训练的小型**轨道偏好模型**，详细快照和成绩见 [训练报告](training-report.md)。尚未完成端到端的音频到 10K/LN 模型，不能把两者混称为完成专训。

## 已完成

`collect_corpus.py` / `collect_author_corpus.py` 收集固定来源，`audit_corpus.py` 检查模式、键数、重复、LN 和轨道冲突；`train_layout_network.py` 的 `records_and_groups` 合并歌曲名、谱包和音频哈希的关联组。划分在歌曲组层级完成，同曲多难度不独立抽签。

训练快照 2078 份合格图，限制每歌曲组样本数后实际使用 1790 份。`train_layout_network.py` 训练 101 特征、64/32 隐层的 pairwise MLP，比较人工轨道排和随机可行排。6K/7K/10K 达到启用条件，8K/9K 验证组不足，保持关闭。新下载数据不会自动进入已发布模型。

真实音频配对审计见 [audio-audit.md](audio-audit.md)，新增 10K 验证的预定协议见 [audio-extension-protocol.md](audio-extension-protocol.md)。用户个人公开谱面仅作风格统计和回归，没有加入这次轨道训练。所有原始音频 / 谱面留在本地。

本轮另训练了起音取舍与 LN 收尾探针，均未接入应用：含强弱拍标签的取音模型相位敏感，去拍标签版本未通过新增歌曲门槛，收尾模型损害长 LN 的保留。完整失败记录见 [学习实验](preference-research.md)。它们不能算作已发布的音乐生成能力。

## 仍需要的数据

键数、谱师、曲风、LN 持续长度、同时占轨和手布局应分层采样。原创 LN、Inverse、转换图需要人工复核标签；未标注的转换不能靠标题过滤完全识别。10K 的 5+5 与 4+6、8K 的均分与 7+1 不应混训。

现有并查集可合并已知元数据 / 哈希关联，同曲不同编码且元数据缺失仍可能漏合并。下一轮增加音频指纹和抽样人工核查，冻结 train / validation / test 歌曲清单，保留独立测试集不参与调参。

真实声音标注与人工谱面选择是两种标签。前者需要起音、有效持续段、混响、呼吸和乐句结束的人工听辨；后者用于学习密度、表达声部与键型偏好。不能把人工没有写出的声音都当成检测错误。

## 两个训练任务

**音乐物件选择**：给定多声部证据、段落和难度，预测值得表达的起音、LN 持续与收尾。保留物理持续音、人声跨音高连续段和编排收尾三种依据。小样本起音偏好实验应先在新歌曲上验证，达到预定门槛才能作为有界软权重接入；不能用它修补错误 BPM。

**保时键型编排**：给定固定起止对和键数，在完整 LN 状态下分配轨道，保留跨窗口按住 / 放键状态。当前 MLP 只看两排历史，下一轮需要更长段落上下文、多步生成评价及玩家偏好对。6–10K 分开验收，不能由大量 7K 样本掩盖 10K 退化。

Mapperatorinator V32 mania 可作为后续端到端基座。先验证数据筛选、键数采样、LN 起止配对与跨窗口状态，再决定全量微调或 LoRA；默认上游 LoRA 配置面向 standard，不能原样用于 mania。训练需要足够 GPU 算力，alpha.4 的 CPU 小先验不能替代它。

## 下一轮验收

- 音频：独立人工标注的起音 / 音尾误差、持续音漏检与混响误检，分乐器、曲风和混音复杂度报告。
- Timing：恒定 / 特殊小数 / 变速分组，报告自动通过率、错误接受和被阻止的正确结果；人工修正与自动路径分开。
- LN 表达：长期持续依据、乐句边界、释放节奏、短键配合，使用同歌同难度试听和玩家盲评。
- 定轨：物件不变量和零冲突是硬约束；快速同轨、短释放和手负担只作可解释线索，不能代替手感。
- 对照：原版 Mapperatorinator、无学习的证据编排和训练模型同时报告，保持歌曲、密度目标与可用声部一致；完整保留失败。

工作台后续可积累“音频证据—生成—人工修改—玩家选择”的本地训练样例。扩充可审核的数据和偏好反馈比继续堆参数更重要。
