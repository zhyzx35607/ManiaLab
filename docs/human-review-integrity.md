# 人工听审与试打记录

本流程只保护材料身份、评分原件和解盲顺序，不评价音乐质量，也不能证明评审者没有提前查看标签。评分表、音频、谱包和解盲映射都留在 ignored 的本地目录，不加入提交。

## 建立记录

- 每次评审使用新建的 `workspace_exp/<run-id>/`，先记录源音频/谱包的 SHA-256、版本、键数、BPM、Offset 和制谱提前量。
- 盲听/盲打条件用随机或中性名称呈现。保留原始参与者填写文件，不在原件上覆写修订。
- 记录真实执行过的内容：是否听原片、是否试听谱面、实际打过的键数、问题时间点及具体声音/手势。未做的项目标记为未做，不从模型报告推定完成。
- 如需解盲比较，先保存评分原件及其摘要，再保存解盲映射；不得用解盲后的解释回写成盲评原始答案。

## 校验工具

`scripts/check_blind_review_scores.py` 检查支持的钢琴听审或键型试打表结构和身份；`scripts/check_music_issue_ledger.py` 检查逐问题处置记录。校验通过仅说明输入结构和摘要符合要求，不证明参与者身份、盲法、完整覆盖或总体音乐验收通过。

## 最终判断

应分别说明声音检测、声部/段落表达、Timing、LN 与演奏手感。测试数量、候选匹配率、模型置信度和合成便携检查都不能替代真人试听与 osu! 实打。反馈仅覆盖其实际歌曲、音源版本、键数和片段，不自动推广为普遍结论。
