# 泛音重合也会覆盖真实弹奏，不能单独删音

对11段已有真实钢琴录音的5005个冻结候选，应用与《樱花草》疑点相同的频率关系定义：起音相差不超过30ms、较低候选第2–8泛音、频差不超过35 cents。这里只计算候选音高/起音的重合，没有重新跑模型、重新匹配、删除音符或生成新谱。

| 候选类 | 已有MIDI起音匹配：重合 / 不重合 | 未匹配：重合 / 不重合 |
| --- | ---: | ---: |
| frame_inactive（47） | 3 / 7 | 9 / 28 |
| 其他（4958） | 736 / 4020 | 62 / 140 |

在12个既无frame持续激活、又满足低音泛音重合的候选中，有3个已经匹配独立MIDI起音。若仅用这两个条件直接剔除，会删除这些原本有匹配的候选。此处没有进行删除后的重新匹配，不能把3写成最终净召回损失。另有736个普通候选也同时满足该频率关系并匹配真实起音，更说明真实八度或和弦叠奏不能只靠频率整倍关系排除。

匹配沿用此前同音高、50ms容差的一对一记录，目标为前60秒，伙伴可取70秒输入中的较低候选。它不是手指松键或完整音长验证；未匹配也不等于听觉上不存在。所有样本曾用于开发观察，本次参数来自四个先前疑点，不是盲测，也没有证明“重合就是真泛音”。

独立复核没有调用伙伴搜索helper，而以全部事件双循环和频率比重新计算，5005个目标的伙伴ID、泛音阶数、频差全部吻合；4766个旧匹配保留，输入和产物hash均核对一致。没有运行删除后的重匹配。

结果支持继续保留候选：需要独立起音与多频带持续证据，不能根据`frame_inactive`、很短的输出区间或频率重合自动删音。方法见[固定协议](piano-harmonic-coincidence-protocol.md)，代码为`scripts/check_piano_harmonic_coincidence.py`。逐事件和已有匹配仅留在`test-data/piano-harmonic-coincidence-v1`，公开同名JSON仅含逐曲计数和运行身份。报告SHA256：`67b3470d6243271e12519d06d74b4cf5b06a8cc8d64849fcfe85d43dc4eba529`。
