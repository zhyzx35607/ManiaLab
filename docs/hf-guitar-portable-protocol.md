# 吉他模型进入便携运行时前的数值检查

必须先完成两份原始权重的全120次转录，才能导出被完整结果支持的候选。
本协议仅验证运行时搬迁，不因导出成功宣称歌曲质量已验收。

`scripts/export_hf_guitar_onnx.py` 使用严格加载后的原网络导出四输出头的
opset17 ONNX。输入固定为原比较队列第一份录音的第一10秒窗，原PCM、重采样
hash和已冻结Torch窗口逐项核对。ONNX checker通过仍不视为可发行模型。

`scripts/verify_hf_guitar_onnx.py` 在应用Python/ONNX Runtime环境重跑全部60份
原始完整录音，2/1 CPU线程、顺序执行。每个10秒窗与原Torch输出比较，容差
rtol0.001、atol0.0001；记录各输出头最大误差。原窗口、5秒hop、物理帧mask和
解码阈值均不变，要求逐音事件数、音高、力度、音尾原因及可观测性完全相等，
每个起尾时间变化不超过1ms。输出独立保存，不覆盖原比较，也不在失败时放宽容差。
完整队列还检查两模型×60个唯一case的原顺序，不能靠120行计数冒充完成。
每份保留拼接激活、时钟和物理mask，另报onset_score误差；以原评分器重新计算
起音/完整区间及可评分范围，明确记录匹配数和F1变化。小于1ms也可能跨容差
边缘，不能默认数值接近就代表评分完全相同。

只有全部通过才考虑接入应用。研究ONNX图不直接替换钢琴模型：吉他只有四头，
没有钢琴的三个踏板头，必须单独标识模型、源码、阈值及缓存。
该路径可复用现有ONNX Runtime，避免为吉他额外携带一套Torch便携运行时。

后续仍需检查实际Nova 22050Hz浮点分轨的重采样、静音、串音与候选编排。
不能将浮点分轨转int16或读预览WAV作为应用输入；原声轨超过1的采样也保留。
仅明确guitar轨可以选择吉他模型，不能自动把other整轨当作吉他。
未经尾部资格检查的事件保持短键，不能把CRNN同音重弹截断当作LN放手。

## 首次严格失败后的诊断补充

首次导出已通过checker，图SHA256为
`e02ee3b540717bcae07678764847f5e078213be12b1cba98400f091019df73f9`。
首次全窗校验在固定第一份录音失败，不能称原协议通过；原plan和runner保留在
`test-data/hf-guitar-fl-onnx-verification-v1/`。

随后单独的`scripts/diagnose_hf_guitar_onnx.py`对第一份完整22.324秒录音检查
ONNX默认优化和禁用优化两模式。默认模式velocity有1274个全窗数值超差，
最大0.025289；最早在第4窗（起点15秒）的frame976，即24.76秒，已超过
真实音源末尾。其余三头以及拼接裁切后实际被解码的四头均通过原容差；128个
事件的音高、力度、尾来源一致，默认模式最大端点差0.000954ms。
禁用优化仍有补零尾部差异，不能据此声称已修复导出。

为检查上述现象是否仅限第一份，后续验证不在首次有限数值差异处停止，而是
保存全部60份的窗口与事件，分别报告全窗、实际物理帧、事件和评分四项状态。
所有容差、输入、拼接、解码规则保持不变；全窗不通过仍会在保存总报告后退出1，
并明确`original_all_window_protocol_passed=false`，不能把新增的物理帧检查
冒充原协议通过。仅第一份未影响事件不足以批准便携应用或忽略其余录音。
