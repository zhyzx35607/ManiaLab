# 起音后延迟持续激活的解码诊断

2026-11-09，在新增规则评分前固定。已经观察到部分 `frame_inactive` 候选在起音后20–50ms出现持续激活，因此这不是完全未见数据上的假设。现阶段只在研究脚本产生建议区间，正式 `manialab.piano.decode` 保持现状。

冻结现有起音、音高、力度和事件顺序，不补音、不删音、不移动起点。不改变起音/音尾/持续门槛0.3/0.3/0.1。仅对旧解码中从未成立持续激活的 `frame_inactive` 诊断：从起音帧起最多等待5帧（100FPS下50ms），并必须在下一次同音起音、6秒限制与输入末端之前。该50ms是本轮明确设定的有限诊断窗，不是训练论文所保证的延迟，也不是按评分搜索出来的最优值。

记录最早激活、连续活跃帧数、第一次回落及offset峰。单帧激活视为孤立证据，不延长；至少连续2帧才允许提议。必须等到真实frame回落，或者该活跃区间内符合既有选择条件的offset回归峰，才可给出新结束位置。活跃之前的offset峰、等待上限、重弹及输入边界均不能伪装成检测音尾。右侧不足或一直不激活保留未知。第一段孤立激活后不继续搜索更有利的后段。

先测试0/20/50ms延迟、超窗激活、始终低、孤立尖峰、早offset峰、重弹阻断、活跃段超边界等构造控制；之后一次性重放已有11条自然钢琴70秒激活。评分沿原协议仅取前60秒起音，按键与CC64延音两套标签、两种容差均保留；MIDI只进入评分，不进入诊断。逐曲列出改善和退步、改变数量及不变的起音/音高身份。原始输入不重跑网络。

《樱花草》仅展示同规则的无真值诊断，不用Reference、红线或量化决定音尾。物理延音建议不自动等于LN放手，声学指标的局部改善也不代表音乐验收。
