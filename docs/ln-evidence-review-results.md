# LN来源快照与完整歌曲复核

2026-11-17。本阶段补足LN尾端检查与证据追溯。完整歌曲的选音、起止和轨道保持不变；新增检查入口不代表自动采音、物理音尾或音乐质量已通过验收。

## 从实际结果发现的缺口

沿用《樱花草》已保存的revision 13分析，完整283.84秒、13个结构段、6,053条候选。默认10K生成1,514个物件、434条LN，85个保留起音和74条LN尾端相对量化前表达移动超过30ms。现有界面只列起音，较大的放手移动缺少同等入口。

`evidence_end`是在表达策略之后、量化之前保存的制谱时钟尾端。起音策略可能已把检测持续音改成短键，人声乐句则可能延长到另一份活动证据的末端。因此它不能一概叫作“检测音尾”。人工将短键改成LN时，这个区别更明显；人工新增音符也不能叫作音高检测或频谱瞬态。

重新分析会保留旧候选供用户比较，候选ID可能再次出现。直接拿旧候选ID查当前分析，会串接不同分析的证据。编辑API又会清除旧选择决策，不能依靠决策表永久保存来源。

另有已复现的独立边界：10 BPM、3等分时，1100–1800ms乐句的两端可同时量化到2000ms，形成短键，但原来被覆盖的内部候选仍写作`represented_by_phrase`。现在清除塌缩短键的乐句标志，并将该代表关系标作`phrase_not_selected`。本修复纠正表达记录，没有自动补回省略音，也不改变选音预算。

## 数据和界面约定

新生成候选保存`source_evidence`，生成时按最终输出物件ID索引：

- `detected`：当次分析的原音频起止、声部、音高、来源、强度、音尾来源与模型乐器标签。
- `expressed`：应用表达策略后、提前量和量化之前的原音频起止，乐句标志、支撑候选和音尾来源。
- 音符的`evidence_start/evidence_end`继续保存量化前制谱时间；实际`start/end`是可导出的谱面时间。字段原意不变。

快照只复制选中物件所需的字段。编辑继承快照，新增人工音没有检测来源；删除音符时，活动候选也保留其来源快照作为历史证据，删除的`before`记录在`edits`中。因此，编辑候选的`source_evidence`可能包含当前`notes`中已不存在的ID；检查当前物件时应将快照ID与`variant.notes`关联，历史快照不表示该物件仍在谱面。波形用橙色实线标出当前谱面音符的原始起音，用灰橙虚线标出不在当前谱面的历史起音。分析 JSON 保留历史`source_evidence`与`edits`；`.osu/.osz`导出仅按当前`variant.notes`输出物件。局部重写的锁定物件继承旧候选快照。新格式候选缺少某物件快照时保持未知，不能从新分析补猜。完整原分析与音频继续留在本机项目。

局部重写还保留区域外物件的人工编辑记录，区域内重新生成的物件不继承旧修改。
如果重分析后同一ID从锁定区域移动到重写区域，会拒绝组合并要求重新生成整谱，避免保存
两个同ID物件或将新物件绑到旧快照。新候选已有`source_evidence`字段但某ID缺失时，来源
明确未知；整个字段不存在的历史候选只允许从自身旧决策表恢复已知时间。历史局部候选中，
起点不在重写区间内的锁定物件也保持未知，避免借用当时的新分析；边界与生成器一致为
制谱起点的左闭右开区间。

谱面检查分别提供起音和尾端的大移动计数及定位；尾端按钮定位到对应候选自己的放手位置。检查器区分原检测、表达和实际谱面时钟，明确人工修改、模型预测与未知来源。`duplicate_pitch`界面说明为量化后的同声部同音高合排，不能据此判断原音频有重复检测。
