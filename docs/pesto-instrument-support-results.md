# PESTO 的实际接入与结果

PESTO已下载并在Windows CPU实际运行，新增的可复用入口为
`scripts/research_pesto_pitch.py`。它保存逐帧音高、发声分数、能量、激活及
物理采样时钟；尚不进入默认采音或LN决策。

固定28个独奏与7个混音全部完成。原输入不归一化，执行前固定voicing至少0.5、
音高误差至多半音、至少半个候选区间得到支持。直接用该规则过滤Tsumugi候选
明显失败：

| 输入 | 原起音F1 → 过滤后 | 原完整区间F1 → 过滤后 | 原匹配起音 → 过滤后 |
|---|---:|---:|---:|
| 28独奏 | 92.44% → 28.64% | 87.74% → 28.54% | 1595 → 283 |
| 7混音 | 86.81% → 19.21% | 73.76% → 16.31% | 1431 → 179 |

逐音检查发现有正确音高轨迹却低voicing的真实弦乐音。这里的发声分数不能
直接当作候选是否正确的证据；低音提琴的两例会被该过滤规则全部删掉。
这不是模型完整转录成绩，而是把一个F0模型拿来筛候选的失败对照。
独立复算28独奏的65465个单音参考区间帧，有62317帧音高在半音容差内，
但同时达到voicing门槛的正确帧只有14428。此为音符标注区间上的一致性，
不能当逐帧F0真值；也说明这里不能声称音高模型全面失效。

看到该失败后，又用**相同已保存输出**做单项事后消融：忽略voicing，仅保留
音高与覆盖条件，不重跑模型、不搜索阈值。独奏起音F1为91.02%、完整区间
86.64%；删掉67个预测，只去掉12个原误采，同时丢掉55个原匹配起音。混音
起音F1为39.36%、完整区间33.65%。小号和圆号有少量改善，但整体仍下降，
不能按这个结果挑乐器自动套规则。该消融是对已见结果的诊断，不是独立验证。

四秒控制中，静音400个有效帧全部低于voicing门槛；MIDI57和69纯音中位音高
分别57.01和69.00；MIDI40纯音却为40.93，偏高约0.93半音。57+69双音只返回
57的中位轨迹。因此既不能只看静音通过，也不能把单F0未覆盖的和弦音删除。

实际运行35个片段累计约231秒，不含初始化；每条约5.09–10.00秒，对40秒
音频。此为本机CPU两计算线程的实测，不推广到其他机器。完整学习权重严格
匹配，原始数组有限且维数一致；未使用上游宽松权重回退。

额外修正了适配层的时间表达：按实际整数采样hop保存帧中心，而不直接累加
请求的10ms。22050Hz下实际hop为221样点，60秒录音两种时钟末端相差约
136ms；16000Hz本次对照两者一致。补帧保留原值但不计入区间支持。
