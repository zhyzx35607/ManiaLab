# 音色分组的已知乐器对照

2026-11-11，在本轮推理前固定。目的是判断Tsumugi音色分组是否能减少错误
类别切换，避免把《樱花草》里的大量改名直接当成声部改善。本轮不搜索新
模型，不改起音、音尾、音高、密度或应用默认。

沿用已经完成采音的全部35份URMP输入：28独奏、7混奏，最多40秒上下文、
0–30秒评分。实际覆盖小提琴、中提琴、大提琴、低音提琴、萨克斯、小号、
圆号和长号；不包含长笛、单簧管、吉他、合成器或人声。单轨和混奏复用
演奏，分别汇总，不将它们当独立样本合并给出总成绩。

复用原Tsumugi全部预测，包含错误类别、额外音和鼓预测，不按已知乐器过滤。
旧 `12-1-vn` 推理在核验输入、权重、源码、参数及完整事件后复用；其余34份
串行推理。全部推理结束后才读取逐音参考标签。公开样本已用于其他模型比较，
模型训练重叠未核实，因此不是盲测或已证明未见过的数据。

模型和参数仍为[先前协议](instrument-refinement-protocol.md)：同一56 MB
权重、8秒窗、4秒步长、距离0.25、最少2音，不传stem或类别先验，不扫阈值。
CPU算子2线程、跨算子1线程。原事件包含的鼓预测保留为不支持的类别，不丢弃
后再计算成绩。保留逐音logits、embedding、窗口观察次数、聚类和分类记录。

比较三个版本：原采音类别、逐音新分类、聚类后新分类。采用冻结源码的
`instrument_merge.json` 将参考GM program映射到相同的广义类别，仅在临时
计分副本的program字段承载类别ID，绝不输出成新的MIDI program。
这组输入只能评价strings、sax、brass三类，不能证明能区分两把小提琴。

原始起音和完整区间匹配必须逐项复现旧基线。新增类别要求的匹配同时检查
起音、音高和广义类别，使用全局一对一分配，避免同刻同音高重叠时任意配对
造成假分类结果。所有误检仍在分母，错误分类不能靠删音改善。
50ms起音／max(50ms,参考长度20%)音尾和40/80ms两套口径均保存；后者对
短音尾不一定更严格。越过评分末端的预测音尾不剔除。

不以标签数量减少、聚类数量或最高softmax作为正确性标准。如果已知类别
匹配没有稳定改善，就不用于自动改名或段落角色选择；有改善也要继续检查
真实Nova声轨里的混组与编排副作用，不能直接称为LN或音乐验收通过。

入口：`scripts/check_instrument_refinement.py`；计分控制与查询控制18项通过。
尚未运行时不报告声学或分类成绩。所有逐音输入、模型和产物均留在忽略目录。

```powershell
.venv/Scripts/python.exe scripts/check_instrument_refinement.py --output test-data/instrument-family-validation-v1
```
