# 从实际音频激活发现的音尾语义错误

检查《樱花草》215.853–227.853秒片段时，四个高音候选只有6–10ms。回读完整音频推理的激活发现：它们有起音峰值，但在解码区间内的持续激活没有超过原有0.1门槛。旧解码器仍把紧接着的低frame值记成`frame_decay`，并声称`release_observed=True`。没有先成立的持续，不能据此声称观察到了消退。

已修为`frame_inactive`：保留原始起音、音高、力度、起止时间供核查，只撤销该音尾的可靠释放标记。自动表达与LN选择共用的未知音尾集合已包含此原因，前端音符检查器显示中文说明。原始音符未删除；持续模型与起音模型意见不一致，也不能单独证明起音不存在。原激活缓存可以复用，重新运行分析即可得到新语义；已保存的旧分析不会被静默改写。

使用原有11份SMD真实录音激活和《樱花草》完整Nova钢琴轨激活重解码：

| 范围 | 原有事件 | 音尾标为未知 |
| --- | ---: | ---: |
| 11份SMD录音完整已推理窗口 | 6122 | 56 |
| 《樱花草》完整钢琴轨 | 1557 | 89 |
| 合计 | 7679 | 145 |

所有7679个事件的音高、力度与浮点起止时间和冻结旧输出逐项相同。《樱花草》的应用缓存逐数组等于便携推理结果，缓存PCM身份对应原Nova钢琴wav，1557个应用候选也逐项核对；89条变更全部从`frame_decay`改为`frame_inactive`。没有重新推理、读取参考标签、训练声学模型或搜索门槛。

两个直接反例已加入控制：只有起音峰、frame从未成立，即使另有offset峰也不能声称观察到释放；确实有一帧持续激活再下降的短音仍保留为`frame_decay`，没有用最短时长一刀切。自动表达测试同时确认未知音尾不能凭空增加活动覆盖或触发LN。相关22项测试通过。

这项修复只纠正音尾证据的含义，不声称采音精度或听感提高。额外探索看到部分候选的frame会在旧端点之后才上升，因此它们也可能是解码过早结束；不能把“当前区间未成立”写成“之后永远没有声音”。是否延长或删除需要独立声学证据，当前不作此改变。

复现：`.venv/Scripts/python.exe scripts/check_piano_release_semantics.py --output <新的本地目录>`。初次执行在输出目录创建前发现便携旧运行没有`runner-snapshot.py`；改为验证其实际保存的`runtime-snapshot.py`后完整通过。公开统计为[JSON](piano-release-support-2026-11-09.json)，原音频、激活和逐事件记录留在忽略目录。本轮没有发布新安装包，音乐验收仍未完成。
