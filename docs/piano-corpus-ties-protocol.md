# 训练与验证语料的已导入延音线审计

2026-11-09，在本轮首次解析原始语料之前冻结。范围固定为 `dataset-v2/manifest.json` 中 `status=ready` 且 `split=train/validation` 的 173 份原 MusicXML：157 份 train、16 份 validation。manifest SHA-256 为 `b8e8e2046fd02acf02dfff1d38969ab4a5de8130f1d32e4a75eaf9659c0da7e1`，准备器快照为 `ae2547f445d59c005b9827ecc470ffe5242d42c91031cdef5c4bfbd1a57db1a1`。不读取 test 数组或原谱，也不读取被排除及不可用文件；不改缓存、不训练、不载模型、不修改上游或应用。

已只读核对全部入选 train/validation 缓存：每份恰有 16 个小节，每小节有唯一 `measure_bounds`，所有 onset 均在所属半开边界内，缓存 note ID 无重复。准备器原逻辑是在已拆 tie 的完整 note array 上取最前 16 个有音符的小节，然后过滤非正时长及钢琴音域以外的音。此次可以使用保存的 16 组边界定义同一时间窗口；仍必须从重新解析的处理后数组复现准备器流程，并逐字段与原缓存 notes/measures/measure_bounds 比较。没有通过精确比较的文件不得计入“同缓存窗口”总数，保留其错误和完整原文件统计。

每份源文件独立导入两份原始 score。两份在处理前的书写几何和已导入 tie 指针必须一致；一份只作参照，另一份调用原版本 `remove_ties_acros_barlines`。分别记录原/处理后完整 note array、tie 指针关系、原始起止/小节/谱表/voice 身份摘要，以及预处理返回的 ID 数。原始参照分支和所有书写时段必须不变。若导入、处理、数组或缓存复现失败，逐文件保存阶段、异常、warnings 和已获得的完整统计，继续其余文件，不静默删除失败例。

“已导入 tie”定义为导入对象中 `tie_next` 与反向 `tie_prev` 关系的并集，同时报告双向一致及单向不一致数量。主统计分别记录这些已观察关系在处理后被删除、保留或新增多少；按两个端点的原小节标签区分同小节与跨小节。已有七例控制证明同小节删除是实际错误，而跨小节删除是原函数的设计行为。不能将两者统称同一种错误。若存在导入关系不一致，必须单独标出，不能将其当作可靠的源 XML 真值。

同时报告完整原文件与相同缓存窗口两种口径。窗口中的 tie 按目标书写片段起音落窗统计，并另报两端均在窗内、从窗外进入或从窗内离开；源/目标时钟用各 part divisions 与 note-array 公共 divisions 的精确整数比例换算，并保留换算身份。窗口 tie 统计是书写结构统计，不自动经过音域/正时长过滤。note-array 窗口统计则应用原缓存相同的有效音过滤，并比较事件键 `(id, onset_div, pitch)` 的多重集合：分别报告新增、消失、净增加，以及既有事件时长改变。完整原文件同时提供未过滤与相同有效音过滤统计，不将 tie 数与新增事件数强行等同。

本审计不逐条解析 MusicXML tie 声明，不修复已知的 Partitura 并行同音漏连。因此只量化“成功或部分导入后能够观察到的关系”的预处理损失，不代表原文完整 tie 数、导入漏连率或真实乐音数量。持续的记谱事件仍不等同于音频中可分离的起音、旋律身份、手指松开或 LN 放手。
