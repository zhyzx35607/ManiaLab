# Transkun 钢琴声学对照协议

2026-11-10，在新模型首次前向推理前固定。本轮沿用已公开的83个独立声源控制及8个同幅度独奏补充，检查另一种声学模型是否减少弱叠奏漏采和延音重复预测。不训练、不调整阈值、不从结果挑选输入，不改变现有应用。

## 固定来源

官方仓库 `https://github.com/Yujia-Yan/Transkun`，commit `c5cb8370e17b4a1650b5971ba87ee4b0d208e5b6`。完整27个文件均与官方Git tree的长度和blob SHA1核对；另记录SHA256。默认 `transkun/pretrained/2.0.pt` 为56408978字节，SHA256 `50a80010effc2a59ffcd068a95cd2b29bd7f23a27a3515bc3ccd209c89a3d44c`。使用同行 `2.0.conf` 的全部字段，不用类默认值代替。`weights_only=True`读取，优先 `best_state_dict`，否则 `state_dict`，必须strict加载并逐tensor一致，缺失或多余键停止。模型eval、CPU、2个intra-op/1个inter-op线程，无梯度。

官方README描述默认权重为无踏板延长的钢琴转录模型；现有Kong模型训练目标包含踏板延长。两者音尾语义不同，本次**只评分起音，不比较自然松键、踏板音长或LN长度**。源码和权重只用于隔离研究，尚不进入便携应用。

读取实际16000Hz float32 PCM，不经pydub或整数化。以`resample_poly(441,160)`转到44100Hz，10秒输入严格为441000样本，保留时间原点；不归一化、不吸附拍线，不再从44.1kHz原AIFF另造更高带宽输入。保存实际传给模型的重采样数组及hash，来源组件身份仍沿用已审计原控制。上游网络内部的特征归一化保持源码原行为，不与外部自动增益混淆。

原音锚点±100ms、全部同音高一对一最大匹配和最小总时差规则沿用。完整保留超出10秒的钢琴预测，不能裁出分母。输出负pitch `-64/-67`是踏板控制事件，单独保存与计数，不伪装成钢琴音符或悄悄丢弃。任何其他异常音高、非有限时间或倒置区间停止并保留错误。

## 官方解码与来源记录

调用未修改的 `TransKun.transcribe`，原配置16秒窗、8秒名义hop，`discardSecondHalf=False`、`mergeIncompleteEvent=True`。实际上hop按1024样本向上取整为353280样本，即约8.010884秒；输入两端各补8秒。10秒输入将有4个推理窗，时钟依据实际样本数，不按窗号乘8秒重写。各窗原始事件在上游修改对象之前复制，连同`forcedStartPos`、`lastP`、`hasOnset/hasOffset`及本窗时间原点保存。

上游会合并不完整事件、替换相交重触发、强制最后一个事件的`hasOffset=True`，随后过滤和处理重叠。本次保留其完整官方输出，同时保存分窗原始记录；最终`hasOffset=True`不能被称为声学确认的放音。不会在本轮根据控制标签修复或替换解码器。另选固定的 `g1-60-72-repeated_high` 原输入作一次不带记录包装器的官方路径核查，要求事件逐字段一致；这次重复推理只验证包装器，不算新增独立案例。

## 结果与决策

完整报告91例，并逐gain/条件列出加入起音数、匹配、缺失、额外预测和踏板输出；相同高音PCM幅度的独奏/弱叠奏另作16对比较。与保存的Kong结果直接配对，保留两模型各自新增的漏检和额外预测，报告耗时但不把不同后端/分窗数量的时间称为公平速度排名。

改善的最低条件是弱叠奏的已知漏采减少，同时正常单音、正常叠奏、延迟和真实重弹没有新的漏采，额外起音不增加，静默保持空输出。任何取舍均按实报告，不因一项改善而默认替换。即使全部条件满足，也只能支持继续真实录音和Nova分离歌曲对照，不能认为9个单音的一次录音会话足以代表音乐质量。若控制改善，将在既有11份SMD真实录音同范围和原Nova钢琴片段做后续检查，协议另行固定，旧SMD始终称历史回归资料而非独立盲测。

源码/模型/输入/runner身份、依赖版本和全部输出都保存。断开观察只继续原进程；确需恢复时只能在相同身份下续未完成输入，不重启已经完成的推理。内存或兼容性失败保留原报错，不通过缩短窗口或删除困难输入伪装完成。
