# 同一声部的起音组与表达层数

2026-11-09。修复“物理和弦音高多于谱面容量时，整组节奏被省略”的机制，并降低主声部偏好压过对音证据的程度。声轨检测结果保留；仍未完成音乐验收，没有发布新包。

## 从完整流程发现的问题

用《樱花草》原始混音和作者实际使用的六个Nova声轨，完整运行采音、自动分段、自动声部方案、取舍、定轨与.osu导出。没有读取Reference或成品的音符、书签；选择无人声方案，其他参数使用默认值。分析自行估计Timing，仍得到148 BPM、原音频Offset 204ms且不稳定；生成对照明确给定74 BPM、谱面Offset 178ms、四细分及22.5ms提前量，**不是自动Timing验收**。

原通用钢琴检测2203个候选，专用检测1557个；其他声部候选逐项来源未切换，跨声部串音过滤均为0。专用钢琴复用已核验的全曲网络激活，导入PCM逐采样一致，不能将本次29秒暖运行称为完整新网络推理。

但原取舍流程中，专用钢琴最终只留下65个note，其他伴奏占1496个。检查确认：

- 采音中的多个MIDI音高直接增加谱面物件需求。一个声部同一拍线位置的物件数超过 `chord_size` 时，整组选择不可能满足约束，无法用较少层数表示它。专用流程存在99组这种超容量位置，旧选择全部为0；通用流程有140组。
- 工具把主声部整组效用乘5。粗分的 `other` 被自动方案选为主声部后，一些需要较大拍线移动的候选仍能压过更清楚的钢琴和鼓。检测更准并不自动转化成最终谱面改善。

这些计数定位的是程序取舍，不判断作者有无漏音，也不要求输出特定note数。

## 实现

同一声部、同一段落的节奏组现在有多个表达层数选项。每个选项保留该组全部起音位置，允许在同一量化位置用较少的音高候选表达；同一组最多选择一个选项。只有最轻的一层表达本身仍超出密度或占轨约束时，才拆成逐起音组。未选中的组仍可因预算被省略，不承诺任何密度下都能采全曲全部声音。

每个量化位置优先使用检测强度较高的候选，强度相同时按音高和ID稳定排序。这是保守的容量处理，不是已训练的左右手声部或和声理解。保留候选的起止、音高与声部不改，不通过剪短LN腾出空间。原始音频采音证据不变。

效用优先奖励不同的声部起音；同位置附加音高仅获得较小增益，避免一大片复音天然压过其他声部。主声部倍率从5减为2：它仍是偏好，但明确的辅助起音可以胜过需要大幅移动的主声部候选。该修改由“清楚的辅助起音不能被低可靠主声部完全盖过”这一规则驱动，没有按作者谱匹配分数调参。

省音记录新增 `represented_by_chord`、所选代表ID和 `represented_at`。它指同一声部在**量化后的同拍位置**以较少层数表达，不能称所有物理起音严格同时，更不称未选音高不存在。记录中列出的代表必须确实在输出中；静音或整个组未选时不能留下虚假的“已代表”说明。

同一专用输入在6/7/8/9/10K各生成完整283.84秒谱面。v2五种键数均为1591物件、308 LN；本例密度与声部取舍相同，轨道布局随键数变化。均通过无同轨冲突、占轨、逐起止落线与实际.osu回读检查，选择器均返回最优解。所有保留事件沿用选择前的量化起止；降层代表关系逐项核验。相同数量不代表不同键数的难度和手感相同。

新增检查覆盖6–10K下五音和弦在低密度时保留连续起音、未来段落降低持条容量时保留完整音尾、静音不声称已表达，以及清楚辅助声部与有/无明显偏移的主声部竞争。全量340项测试通过。前端省音文字语法检查通过；本机浏览器自动化初始化失败，本轮没有完成视觉检查。

## 限制与重现

这是表达层的确定性改动，没有新训练权重。普通模式的 `other` 仍会包含多乐器与串音，自动主声部和分段也未必合理。LN仍由本段表达方案和持续证据选择；本例钢琴方案为短键，较低的LN比例不是“修复了LN”，也没有强行补条到参数值。下一步要继续检查分段主次安排、粗分声部中的真实起音及LN的连贯表达。

汇总、来源哈希与两版全部结果：[机器报告](chord-expression-research.json)。原音频、生成谱、逐事件记录和两个实现快照留在本地忽略目录。固定输入必须来自已完成的六声轨整合检查，不能以人工谱面替换。重现选择与导出：

```powershell

```
