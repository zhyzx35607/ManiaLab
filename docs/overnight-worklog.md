2. LN 的持续依据、音尾和跨音高声部表达，明确区分检测与编排。
3. 各键数的手指布局、LN 释放状态、连贯键型和长上下文搜索。

“超过 Mapperatorinator”是需要独立比较证明的质量目标，不能用测试数量、运行耗时或整齐落线替代音乐性验证。

## 23:30 左右的实际进度（11 月 7 日）

- 已实现同采样时钟的 A/B Offset 试听、原始起音 / LN 放键试听，以及可切换分离声部的毫秒级波形检查。真实浏览器流程通过，390px 宽度无横向溢出。
- 已打包官方 Hybrid Demucs 四声部分离 worker，真实全曲 CPU 分离约 156 秒；逐声部运行 Basic Pitch 并保留人声连续段。已精简 worker 中无关依赖，仍需主程序完整打包验证。
- 完成基于 LN 占轨和手指布局的 beam search。40 份真实谱面片段均保持物件不变量与结构有效；部分同轨统计较旧算法高，不把此统计直接当作手感优劣。
- 发现按时间抢占密度额度会挤掉稍后的强起音，改为全曲受约束的候选选择。固定同一《有点甜》候选、210 / 115 时，人声持续段保留数由 26 增至 50，实际 LN 比例由 30.0% 增至 36.6%。这是加入量化误差偏好前的中间对照，并非发布版最终指标。
- 生成物件保留原始采音起止时间；当密度必须取舍时，降低大幅量化起音的优先级。界面能列出这些位置并直接打开波形。
- 首轮小型线性定轨先验只在 6K/7K 达到验证条件；10K 未通过，8K/9K 验证歌曲不足。尚未将这些权重接入默认生成。继续采集本地语料与改进评价设计。
- 增加 10 首配对人工谱面的本地音频审计。人工谱面是谱师取舍的参考，不是所有可听声音的完整标注。发现 Opus 经两条重采样路径后末尾会差一个采样点，已修正有界的末尾舍入差，起始时钟不动；更大差异仍报错。
- 原版 Mapperatorinator V32 在同曲前 60 秒的 CPU 运行已完成，约 669 秒，337 个物件 / 45 个 LN，最长 857ms。它只是对照输出，不能由 LN 数量宣布音乐性超过原模型。
- 当前阶段完整测试 82 项通过；后续量化来源与 EOF 修正的专项测试通过。单线程 HiGHS 修正通过 75 个跨线程任务的压力检查，没有复现此前的 Windows 原生异常；根因仍未得到单独证明。
- 尚未提交本轮代码、尚未发布新 Release。主程序独立包回归、语料扩充、最终训练验证和文档更新仍在进行。
