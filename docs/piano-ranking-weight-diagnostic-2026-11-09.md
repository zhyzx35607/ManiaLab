# 新负组对原排序权重的影响

保存预测的解析诊断确认：将可证更晚负组并入原均值后，旧负组对正 logit 的绝对梯度贡献被压低。不过，新增容易组实际贡献的梯度很小，最高竞争组仍占较大份额。只能确认权重计算发生了变化，不能据此认定上一轮训练退步的原因。没有加载模型、新推理、反传、改应用或发行安装包。

诊断复用旧排序和更晚负例实验各自 selected epoch 的 validation logits。每套固定 logits 分别计算原组 O 和扩展组 E，四个固定组合区分预测变化与公式变化。它们来自已经用于开发的验证集，不是新的盲测。每个来源音保留全部正目标 P，每个负 tick 组取最高分；每源损失依次对 P、负 tick 平均，窗口再对有负组的源平均。

对一个负组，令 `q=mean_P sigmoid(max_negative_logit-positive_logit)`。该组对全部正 logit 的绝对导数之和为 `q/K`，乘窗内系数后为 `0.1*q/(K*S)`。本页的梯度量指这些 logit 解析导数，不是共享模型参数梯度或 Adam 更新；BCE、网络 Jacobian、梯度抵消和裁剪不包含在内。JSON 的 loss 未乘 0.1，window gradient 已乘 0.1。

## 分母变化和实际贡献

每种输入有36个验证窗口。旧排序981个源、2691个负 tick，扩展后1323个源、19146个负 tick，其中新增16455组；新增342个原来没有异 tick 负组的源。这份验证集没有旧边与新边同 tick 的混合负组。

在981个共同源上，单看组均值系数 `K_old/K_extended`，旧组保留率中位数为16.67%；连同源均值 `S_old/S_extended` 后为13.11%。这是源等权的系数中位数，不能解释成总体梯度或参数更新只剩13.11%。

下面用同一套新模型 logits 计算 O/E，36个窗口等权汇总。容易组要求其对**每一个**正成员的 sigmoid 斜率均不超过0.01，困难组指最高负分至少达到一个正成员分数。

| 输入 | 新增容易组比例 | 容易新增组占扩展正梯度 | 全部旧组绝对梯度保留率 | 原困难组绝对梯度保留率 |
| --- | ---: | ---: | ---: | ---: |
| clean | 99.720% | 0.421% | 61.208% | 64.092% |
| 音尾+1拍 | 93.674% | 0.555% | 22.663% | 27.701% |
| 音尾+2拍 | 89.985% | 0.355% | 19.291% | 20.280% |

全部新增组占扩展正梯度的2.756% / 30.482% / 47.652%。新增困难组只有1 / 139 / 275组，却贡献1.299% / 14.472% / 25.501%。因此不能将“新增容易组很多”写成“容易组的梯度淹没了困难组”。

同981个共同源上，最高负组所占源内正梯度份额中位数由94.93% / 94.99% / 94.44%变为69.60% / 78.83% / 67.66%。精确同分的最高组合并统计，新源不混入这张配对对照。最高竞争组仍获得较大相对份额，其绝对贡献则受上述两个均值分母压低。

旧排序 logits 也出现相同形式变化：全部旧组绝对梯度保留率58.91% / 21.53% / 19.22%。完整六格统计、容易阈值0.01/0.05/0.10和来源身份见[汇总JSON](piano-ranking-weight-diagnostic-2026-11-09.json)。

## 核验与下一步

原诊断8项公式自检通过。另一个不导入模型或损失 helper 的独立脚本从保存图、sidecar及 logits 重建并核对131022条逐组记录，包含损失、梯度、来源类别、困难/容易标记；24项有限差分及六格汇总全部一致。没有把逐事件数据加入公开仓库。

下一轮只检验保留原排序项、将可证晚候选作为独立辅助项的方案。两个目标分别按自己的负组和合格源平均，系数各0.1；这会改变总辅助目标的大小，不能描述成只调整了某一个分母。协议已在训练前固定，见[分开归一化对照](piano-separate-later-protocol.md)。是否采用仍取决于完整和弦、交叉旋律、踏板控制及真实音频后续检查，不由这一诊断决定。
