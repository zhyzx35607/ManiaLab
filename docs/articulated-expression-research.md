# 连续起音、主声部和LN表达

2026-11-09。本轮加入可手动选择的“连续起音优先，组尾可延长”，完成两个固定全曲实验。**自动推荐保持此前行为**，没有把降低LN数量当作解决问题。协议分别为[首轮对照](articulated-expression-protocol.md)和[独立表达](independent-expression-protocol.md)，[统计](articulated-expression-research.json)保留全部中间结果。

## 确认的问题

原自动方案按音符覆盖时间判断主声部，再默认只给主声部使用持续表达。钢琴专用模型包含踏板延音，伴奏模型又有强制窗口截断，检测持续时间不能直接等于人耳听到的主旋律或LN意图。替换other检测后，这一依赖把钢琴设为多段主声部，再生成大量钢琴LN。

本轮诊断统计精确裁剪段落区间、合并重叠活动，并分别报告起音活动、已观测持续覆盖和未决音尾数量。它们不是音色重要性分数；新主次算法仅在研究脚本使用。默认主次建议没有据这些统计贸然替换。

## 可选连续起音模式

每段每声部先以30ms范围组成起音组，不链式合并；相邻起音间距的中位数决定节奏组的分离阈值（2.5倍，限500–1600ms）。至少3组起音，且至少一半相邻起音之间的中位可靠音尾延续超过下一起音80ms，判为拖尾敲击序列。序列内部短键化，末组仍可使用原始、已观测的持续音尾。

该方式只改变表达，不改变原采音，也不向下一音伪造音尾。所有起音保持候选身份；选音/定轨之后不剪尾腾空间。它不是手指松键检测、独立旋律流识别，也可能把左手持续与右手敲击混在同一声轨。因此先作为用户可选方式，默认自动方案和已保存的手动“持续音”保持原来的意图。

操作：展开“先规划音乐 → 段落与声部表达”，在某段钢琴等声部选择“连续起音优先，组尾可延长”，保存方案后重新生成。新模式也可用于其他声部，但需自行试听。高LN倾向不会覆盖已经手动保存的声部方案。

## 《樱花草》全曲结果

复用上轮同一份冻结采音、13段边界和设置，没有重跑网络或读取作者Reference。使用明确给定的74 BPM、Offset178、四细分和22.5ms提前量，不是自动Timing验收。旧方案在当前选择/定轨代码下逐事件、逐轨道复现一致。

|---|---:|---:|---:|---:|---:|---:|
|原方案|1424|698|650|28|20|66|
|只修持续活动统计|1434|726|706|0|20|68|

只修统计反而使other丢掉默认LN资格；第一版起音表达又使全曲LN骤减。这两种结果均保留，没有直接设为默认。第二版允许辅声部表达可靠持续音，避免“非主声部必为短键”，但不据219这一数量认定音乐改善。

第二版鼓物件354→324、钢琴807→849、other180→184、bass83→84。钢琴独立起音组774→813，鼓353→323：钢琴保留更多节奏的同时，鼓仍有取舍退步。大幅量化起音66→71，也没有消失。不能只报告钢琴收益。

使用旧other检测的10K，两个新表达方案都仍为1591物件；第一版317条LN，第二版364条LN，原方案308。旧other检测造成的大幅量化仍为550。这说明编排规则不能代替准确采音。

第二版新other输入6–10K均为1441物件、219条LN，包含24条钢琴、130条other、65条bass；布局随键数变化。所有输出通过无同轨冲突、完整落线、源候选不变、未决尾禁用和`.osu`回读。相同数量不是跨键数手感验收。

## 其他真实钢琴与工程检查

11首此前固定的SMD真实演奏，使用已完成、核验输出一致的激活解码。新表达保留全部强起音和原数据，音尾只能保留原值或表达为短键，未决尾不会成为LN；没有用MIDI长短当制谱真值，也没有重新训练或挑歌。

在Bach、Chopin、Ravel等密集持续音中，大部分强起音被短键化；Bartok、Haydn则没有触发拖尾序列规则。这既说明规则按检测形态变化，也暴露多旋律钢琴被归为同一声部的限制，不能称已学会人类乐句安排。

API检查覆盖保存新模式、生成导出、保留原采音、切回完整持续音；相关专项检查通过，全量362项通过。前端JavaScript语法通过。computer-use初始化仍报`failed to write kernel assets: 系统找不到指定的路径`，没有完成本轮视觉检查。

后续便携打包增加旧音频程序拒绝检查，全量363项通过；dev.2真实EXE在清理PATH、禁用下载代理及中文数据路径下完成四／六声部、6–10K导出和钢琴专用冷／暖缓存检查。12秒真实钢琴片段检测44个候选，连续起音表达输出44物件/11LN、持续表达43物件/30LN。这是固定120 BPM测试格上的工程检查，不是该演奏的对音或音乐质量成绩；两者原始采音均保持不变。

所有代码、报告及原运行快照保存；全曲原声轨、逐事件和谱面仅在`test-data/sakura-benchmark/articulated-expression-v1`、`articulated-expression-v2`。目标仍未完成：需要更可靠的声音流归属、主次段落、鼓选音、自动Timing和基于音乐语义的LN规划。
