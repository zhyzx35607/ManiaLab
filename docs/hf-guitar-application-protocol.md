# 可选吉他模型的实际应用检查

固定输入来自完整浮点探针：第一份完整GuitarSet录音（两种音尾模式）、
《樱花草》Nova吉他全轨与《有点甜》HTDemucs6吉他全轨（默认仅起音模式）。
两个原生输入没有独立吉他标签，不能计算准确率或用Reference未标出的音判错。
保留完整输入和原始幅度，不选更好片段、不调模型阈值、不读预览WAV作模型输入。

`scripts/check_guitar_application.py`启本地源码HTTP服务，
`scripts/verify_portable.py --guitar-only --guitar-probe ...`启真实EXE。
两者复用`scripts/verify_portable_guitar.py`，顺序执行以下检查：

1. 由固定NPY无损写float WAV，原歌曲作mix；通过真实上传API导入。
   FFmpeg解码和持久化NPY必须逐采样相等，来源文件及研究产物先验哈希核对。
2. 使用实际GuitarDetector、实际ORT与真实磁盘缓存，禁止mock网络。
   全部原始候选trace与浮点探针逐字段比较；研究评分器额外添加的program、
   is_drum、voice三项标签明确剔除，声学事件字段全部保留。
3. 以同一完整mix复算既有源能量过滤，核对保留音符与每个拒绝ID；不把被过滤
   候选删除出原始trace。极弱轨即使没有保留音符也继续完成检查，不造音符。
4. 第一份录音分别测试默认未决尾与显式允许模型尾；两种模式缓存隔离。
   全部非空输入生成6–10K并比较导出的时间/轨道/音频，未知尾始终不可成为LN。
   使用固定120 BPM/0ms检查网格契约，**不是自动Timing或音乐对音验收**。
5. 重开服务和项目，分析、表达和已保存谱面保持；重新分析必须复用缓存且候选
   相等。新项目取消实际冷采音后不得留下半份分析，服务仍可用。

源码服务重开与真实进程重启分别报告；只有后者可称EXE重启检查。
清空PATH和不可达下载代理用于便携检查，并不是操作系统防火墙。
声学网络严格串行、CPU计算线程2/跨算子1。

此外，在安装开发模型前运行4秒数字静音控制，保存物理四头、原始事件、模型与
运行时身份。无声输入不能靠源能量过滤隐藏原始误报。
所有音频、权重、逐音trace和导出谱面留在ignored本地目录。
通过上述检查仅证明这条运行路径可用，不代表长条音乐性或10K成品达到用户标准。
