# MusicXML 源持续事件与时钟核验

修正后的源读取层完整核验了固定 173 份 train/validation 原文件：136 份完成，37 份因当前不支持或无法确认的记谱/时钟结构明确拒绝。完成文件中的 239,303 个书写片段保留全部源字段，确认 8,029 条 tie，产生 231,274 个持续事件；190 个片段保持 `unknown`，没有作为确定的起音或延续标签。

| 完整源文件口径 | train | validation | 合计 |
| --- | ---: | ---: | ---: |
| 固定入选文件 | 157 | 16 | 173 |
| 完成文件 | 127 | 9 | 136 |
| 明确拒绝文件 | 30 | 7 | 37 |
| 书写片段 | 219,774 | 19,529 | 239,303 |
| 已确认 tie / 延续片段 | 7,248 | 781 | 8,029 |
| 持续事件，包含未知事件 | 212,526 | 18,748 | 231,274 |
| 已核实书写片段 | 219,595 | 19,518 | 239,113 |
| 未知片段 | 179 | 11 | 190 |
| 显式排除的 grace/cue | 2,100 | 89 | 2,189 |

源读取直接使用 MusicXML 的 sound tie、原始时钟与记谱声明，不采信 Partitura 已解析的 tie 指针。只有同 part/pitch、书写时间精确相接、两端声明相符且互为唯一候选时才连接；明确的 notation number 可以消除并行同音歧义。staff/voice 保留为书写属性，不被当成跨小节旋律真值。

实际执行器为内存 XML 副本中的 note 注入结构路径 ID，再用固定 Partitura 1.8.0 独立导入，逐 ID 比较 part、pitch、quarter 起止、staff、voice。136 份完成文件的比较均一致，时间容差为 `1e-8 quarter`。副本只改变 ID，原文件哈希未变，且该比较没有使用导入器的 tie 指针证明源连接正确。公开汇总核对了保存的比较记录与执行快照，没有重新导入全部文件，因此“逐 ID 一致”是本次冻结执行器的结果，不是第二次独立重跑的结果。

37 份拒绝完整保留，不能当作全部语料都已支持：

| 拒绝原因 | 文件数 |
| --- | ---: |
| grace/cue/rest 上存在 tie，需要单独处理 | 21 |
| backup 越出当前小节 | 9 |
| forward 时长非正 | 4 |
| backup 时长非正 | 2 |
| 不同 part 的控制小节时钟或编号不一致 | 1 |

这表示当前适配范围不足或数据需要进一步核实，不等于这些作品无法使用。另一个[端点类型诊断](piano-corpus-tie-endpoints-2026-11-09.json)已确认，之前 22 份审计缺口中的 165 个外部端点都是已注册的零记谱时长 `GraceNote`。后续需要为这类特殊记谱建立单独语义，不能直接设成普通零长音，也不能凭记谱零时长推断其在音频中没有起音。

190 个未知片段主要涉及未匹配的 start/stop，以及与不确定连接相连的片段；另有并行同音歧义和 sound/notation 声明冲突。单个片段可能有多个原因，所以原因出现次数不能相加当作未知片段数。已核实的独立音仍能成为记谱起音；不确定性只沿相关候选关系传播。

审阅前的初版在 51 条文件记录后主动停止，保留 45 条完成记录、6 条错误及执行快照，没有完整报告。独立自造反例发现三处会误给强标签的问题，并由修正版处理：

- 单边 tie 声明缺少对端时，相关同音高边界候选也保持未知，避免另一端被标成确定起音。
- note 级和 tie 级 `time-only` 条件保留并屏蔽，条件演奏不会被当成无条件标签。
- 不同 part 的控制小节编号序列和精确时钟必须一致；`non-controlling` 当前明确不支持。

新增 9 项独立回归控制在修复版上通过，覆盖上述情况、多个潜在同音对端、无关音高不误屏蔽及正常多 part 对齐。初版结果没有混入本表。

初版保存的 `beethoven_piano_sonatas_08-1` 还有一个具体时钟反例：最早分歧位于第 11 个小节，标签 `X1`，两个 part 的左边界相同，右边界却差 1 tick；统一时钟为每四分音符 480 ticks，即 `1/480 quarter`。修正版明确拒绝该文件，未通过自动舍入掩盖差异。

七个旧自造 XML 也直接经过源读取。六个无歧义例恢复预期事件数量；最后一个无显式 number 的并行同音例保留 4 个 unknown 片段、0 条已确认连接。此前[显式作者连接验证](piano-score-events-research-2026-11-09.md)为该例提供了已知边，得到两个事件；本轮没有把作者边当推理输入，不能要求这两个不同证据条件得到同样的确定标签。

本轮 `musicxml-events-v2` 实际执行约 273.73 秒。公开汇总验证 178 个本地产物、173 份所选源文件与四个执行快照，重新计算保存源表示的计数，并检查每片段唯一归属、合法 tie 时钟、完整字段保留、unknown 与监督掩码一致。没有读取旧训练数组、训练模型、改变权重或启用应用行为。原逐音符表示、声明与 warning 仍在本地忽略目录。

必须区分这次完整源表示与此前[已导入 tie 损失审计](piano-corpus-ties-research-2026-11-09.md)：两者的成功覆盖集合不同，分别为 136 份和 151 份；前者还解析原始声明并屏蔽歧义，后者只统计导入对象关系。不能直接把总 tie 数相减解释成修复收益，也不能将完整文件总数与前 16 小节窗口统计混用。

测试集接触记录保留原事实：开发前为查看 XML 结构曾打开 `K279-1` 前 180 行，随后确认它属于 test；该查看未用于训练、推理或评价。后续冻结运行器仅处理 train/validation。这里的范围声明不抹去此前的结构查看。
