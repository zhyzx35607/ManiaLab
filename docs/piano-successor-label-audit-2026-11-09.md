# 声部连接标签的覆盖与含义

四轮排序实验之后，对136份train/validation源表示和XML、1641份三种观测缓存、27份验证预测做了只读审计。没有训练、加载模型、读取test源或更改应用。两个主要问题是同一时刻的错声部连接，以及没有训练标签却仍参与选择的跨小节候选。

新模型clean输入解码后的287条已监督误连中，260条已经位于正确后继时刻：215条为同谱表不同written voice，45条为不同谱表。前者在train只有2168条，占全部负边1.55%，却构成此处约74.91%的误连。这是覆盖与误差集中现象，尚不能说明重加权一定有效。现有排序辅助项排除了正确时刻内的负边，解码器又保留获胜时刻内的所有非负边，所以单纯加大当前排序损失不会直接处理这些错误。

训练作品中45份将钢琴写成两个part、每part一个staff，80份写成一个part内两个staff；验证作品分别为7份和2份。53份双part文件的两方MIDI program均为1，名字为piano、Klavier或空白。因此part差异不能直接理解成不同乐器，也不能把所有跨part边自动补为负例。已知正确后继时刻的跨part未监督候选为train4871条、validation1367条；后者可靠端点的1312条中，新clean解码选了501条。这501条不在现有FP统计内，当前也不能称为501个音乐错误。

另一项可单独研究的严格子集是：源音有完整、可靠的局部真后继组；未知候选与源同part，两端可靠且所在小节没有排除或未知音；候选时刻晚于这组已知后继。在当前“紧邻后继”的记谱目标下，已有较早确定后继，这个更晚候选便不能是同源的紧邻后继。这不需要假设voice数字跨小节不变，但必须建立新的显式训练协议，不能静默修改旧缓存。

该子集在clean/+1/+2的train分别有581745/603381/629157条，validation为30914/32385/34439条。新模型+1/+2中，被未监督最高分抢走的72/115条真边，有57/87条涉及这个子集。数量太大，直接全部加入BCE会同时改变样本分布；需要先限制每个源和竞争时刻的贡献。没有可靠局部后继的源、同刻未知关系和跨part关系仍保持未知。

还确认了全部缓存的chord_mask均为false。共享编码器在适配时会变动，和弦头没有对应监督；不过上游voice decoder不消费chord logits，当前固定后继解码也只读voice logits，因此不能直接把眼前的voice错连归因于和弦头。

后续按单变量分开：先检查正确时刻内已知负边的排序监督，并单独报告同谱表异voice误连和完整真后继组保留；再研究上述有证明的更晚候选。推理阶段绝不能读取人工staff/voice或真值来排除候选。这些是局部记谱目标，依然不能替代真实音频声部、乐句和LN音乐验收。
