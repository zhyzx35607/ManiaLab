# 贝斯真实录音比较

使用 Fraunhofer IDMT 官方发布的全部 17 段
IDMT-SMT-BASS-SINGLE-TRACKS，不按模型成绩选择片段。
来源：`https://www.idmt.fraunhofer.de/en/publications/datasets/bass_lines.html`，
该页实际链接的归档：`https://zenodo.org/records/7544099`。

20,499,169 字节归档已按官方 MD5 及本地 SHA256 核验：
`fdc36effc0377aa065d6cb378bebd54a817e51f4d65c3531c54a1e8848400fcb`。
数据许可为 CC BY-NC-ND 4.0，仅保存在本地用于比较，不随软件再发布。
最初尝试的旧归档编号返回 404，未使用其内容。

原文件均为 44100Hz、单声道、int16 PCM，保留原样，共 948 个参考音。
XML 保留起止、标注音高、拨弦方式和表现技巧；不把这些标签送给模型。
准备脚本为 `scripts/prepare_bass_benchmark.py`。
固定清单 SHA256：
`5e575417b05674ba23a0d1614643197a97ace1a0d1d533fbdd689987fed3d46f`。

比较现有贝斯处理链与固定 Tsumugi `bass_v2`。现有处理包含贝斯重复起音
抑制、能量筛选、收尾和瞬态校准；新模型使用所有类别，不能用正确标签
删掉其错误的鼓或其他乐器预测。两者完整原音频推理，不归一化、不对齐
参考节拍、不补齐首尾。CPU 两计算线程、一跨算子线程，神经任务串行。

按原始时钟评分 `[0,min(20,音频秒数−2))` 中全部起音，不按音尾位置筛预测。
17 例当前评分窗内均无不可观察的参考尾。完整区间沿用 50ms 起音、
max(50ms,参考音长20%) 尾容差，另报告固定 40ms/80ms 口径。
若预测没有音尾，它仍进入完整区间分母，不能作为正确区间匹配。

保留标注中的闷音、泛音、滑音和推弦音高，不据模型预测改写答案。
因为这些演奏方式的标注音高不总能概括听到的整个声学过程，额外单列
不看音高的起音匹配；这种节奏指标不能冒充正确音高或正确乐器识别。
按技巧报告召回时，先对全例做一次全局匹配再分组，避免同一预测反复
在多个技巧组内算作正确。预测误采无法唯一归到某个参考技巧，不强造
技巧组的 F1。

这是独奏贝斯、单个公开来源的比较，可能与上游训练集重叠；不能称为
未见数据盲测，不能替代混音测试、分轨漏音测试或整曲 LN 验收。
本协议和清单已在首次运行这组模型比较之前保存。
