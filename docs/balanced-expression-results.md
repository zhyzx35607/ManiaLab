# 段落存在、主次与持续表达分开处理

后续核验：下文数字是当时的冻结结果。dev.4 源码另包含 `reattack` 未决尾保护，
它会影响连续起音规则的重叠统计。相同候选在当前规则下的10K选择为1495物件／373LN；
逐项原因、6–10K重放及仍未解决的鼓组取舍见[当前规则重放](expression-current-replay.md)。
两者均不代表音乐验收通过。

2026-11-10。开发分支的自动声部方案更新为 revision 3。它修复“背景持续时间长，所以整曲始终获得主声部加权”的推荐问题，同时保留短暂插奏与跨段活动证据。没有新增采音、训练、音尾或自动 Timing 成绩；便携 dev.3 草稿仍是此前的构建，本轮改动尚未打入其中。

## 现在的自动建议

- 多个旋律声轨都有候选时，先不指定主声部；只有一个有活动的旋律来源时，才建议该来源优先。这里来源可以包含多个预测乐器类别，并不宣称只有一件物理乐器。用户仍可手动指定主声部。
- 删除覆盖率低于段长 2% 就整段不采的规则。达到原候选门槛的短暂插奏也参与表达与后续取舍，不能仅因段落长而消失。原 `strength>=.35` 门槛没有变成跨模型置信度。
- 活动统计分别记录本段候选音组、从上段延续的可用区间、未知尾和精确覆盖率。区间裁在段界内，不会超过 100%。未知尾不能使声部在后段继续显示为活动。
- 主次与持续资格分开。持续倾向为 0 时只表示起音；大于 0、低于 .75 时，钢琴与吉他建议已有的“连续起音优先”，其余旋律声部建议持续表达；达到 .75 时旋律声部建议完整持续。鼓仍表示起音。不强凑全曲 LN 数量。
- 连续起音表达使用整曲同来源、同模型类别上下文，不因切段制造末音。持续音仍只能保留原区间或改成短键，未决音尾不能生成 LN。跨段音继续使用其起音所在段的方案，后段不会补新按键或追溯改前段。

这是可编辑的表达建议，**不是独立旋律流识别或已达标 LN 策略**。已保存的手动主次、持续音、起音、类别覆盖保持原语义，不被自动建议或全局倾向覆盖。

输入为 `sakura-tsumugi-expression-onset-v3/analysis.json`：同一份 283.84 秒候选、13 段、74 BPM、Offset 178、提前 22.5 ms、密度 7、最大同时长条 5。没有重跑模型、读取 Reference 或换音源。原方案在当前选择和定轨器下逐音、逐轨道复现。

全持续方案产生 651 条钢琴 LN，钢琴起音反而减少，未选为当前中低倾向的默认。新默认的 337 条 LN 包括钢琴 9、贝斯 161、其他 167。原方案 314 条全部来自其他伴奏。**这些数量不是音乐质量标签**；其他伴奏被保留的物件减少，也不能把全部减少项都当误采。大移动变少来自选音集合变化，不是自动 Timing 或原采音偏差被修正。

四项求解均正常结束；原方案相对间隙 .004415，其余为 0。记录了求解状态、间隙、目标及界，避免把时限内不同可行解误解为模型差异。不同权重目标的数值不能直接比较质量。

随后在最终源码上跑自动默认的 6–10K，各份计划均与真实应用 `propose_expression` 完全一致。6K 为1495物件/334LN；7–10K各1498/337。五份均无同轨冲突，逐音、逐尾、逐轨道 `.osu` 回读一致，谱包中的音频 SHA 与固定原曲一致。网格检查使用手工时钟，不能证明自动对音正确。13段均不再强行标为 other 主声部；这意味着没有强行选主，并不意味着已经找出了真正的主旋律。

## 其他来源与反例

新增 URMP 39 的五条真实分轨检测作为表达控制。使用已冻结 Tsumugi 推理、重新核对窗口起点和尾部来源，没有神经推理或参考音符标签。不同录音文件定义五个来源，不由模型类别猜测分源。固定每10秒切段只是边界控制，不是声学分段结果。

243个合格检测候选全部进入表达阶段，区间只保留原值或变短键，没有跨段重复造音；以密度7和同时长条上限5取舍后保留174音/166LN。四段均保持多来源未指定主次，跨段活动统计正常，未量化的原起止通过导出回读。这说明控制流程能处理弦管乐多轨，不是174音已经具有合理难度或音乐性的结论。

一个明确保留的失败例：同一钢琴轨中，左手1000–5000ms持续音与右手1000/1500/2000ms连续敲击共存，已有 `articulation` 规则可能连左手也表达成短键。同声轨同类别仍不是独立旋律流。在开发版可将该段改为持续音，后续需要解决声音流归属，不能把9条钢琴LN视为正确答案。自动主次也尚不能按听感分出前景、背景和节奏层。
