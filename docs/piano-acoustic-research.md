# 钢琴专项采音：真实录音与便携入口

2026-11-09。11 首真实钢琴录音的起音与踏板延音区间均有改善，因此增加**默认关闭、只适用于独立钢琴声轨**的 ONNX 入口。它没有解决完整制谱、声部层数或 LN 规划，也没有替换其他乐器的检测器。本轮没有发布新 Release。

按用户最新补充，《樱花草》用于参考清晰的声部组织和表达思路，不要求逐音符复刻；作者也可能有错漏。人工谱匹配是差异诊断，不是声音真值或完成度。具体见[音乐质量目标](music-quality-target.md)。

## 输入与固定协议

数据是 [Saarland Music Data v2](https://zenodo.org/records/13753319) 的 `SMD-piano_v2.zip`，选择真实演奏的 `wav_22050_mono`，没有使用同包 `midi_wav_22050_mono` 合成音。按作曲家分组后取文件名字典序第一首，Rachmaninov/Rachmaninoff 合并，共 11 首。每首只评分前 60 秒起音，网络获得前 70 秒上下文；所有评分窗内起音的预测均保留在分母，包括音尾越过评分窗的预测。

选择规则、阈值和评分方式在推理前固定，见[原协议](piano-acoustic-protocol.md)与[踏板语义补充](piano-pedal-protocol.md)。没有训练、按标签拟合时间偏移、输入人工拍线或事后选择阈值。11 首都不存在参考音尾超出 70 秒输入的问题。公开数据不保证从未参与所有模型的预训练，因此不称完全未知的盲测。

通过 HTTP Range 获取 33 个音频/MIDI/CSV 成员，逐成员核验 ZIP CRC、长度与 SHA256。没有下载完整 3.22GB 归档，**未核验全包 MD5**。MIDI 与 CSV 音高和事件数一致，起点最大约 0.5ms、终点约 1ms 的差异来自 CSV 舍入。数据许可为 CC-BY-NC-SA-3.0；原始音频与逐事件标签仅保留在本地忽略目录，不随应用或仓库分发。

比较原应用的 Basic Pitch＋已有起音融合/音尾检查与 Kong 等人的[钢琴起音/音尾回归模型](https://github.com/qiuqiangkong/piano_transcription_inference)，源码固定为 `0226e74cbc805660e34bbd6a8fed2083890ebb88`，权重 SHA256 为 `c3fa9730725bf4a762f1c14bc80cd5986eacda01b026f5a4a2525cd607876141`，完整严格载入，默认起音/音尾/持续门槛为 0.3/0.3/0.1。

训练源码固定提交 `1ade7dcd4348add669a67c6e6282456c8c6633bd` 的 `TargetProcessor.process(extend_pedal=True)` 包含踏板延音。因此同时保留原 MIDI 按键结束和 CC64 踏板延音两套对照；二者都不等于谱面 LN 放手。踏板参照按通道独立延长，遇到同音高重弹截断，不修改原按键标签。

## 完整结果

标准容差：起音 50ms，音尾 max(50ms, 20%参考长度)，音高必须相同，采用一对一最大匹配。下表为逐曲 F1；“区间”同时要求起音和踏板延音终点匹配。

|---|---:|---:|---:|---:|---:|
|Bach|0.8012|0.9928|0.3072|0.7849|0→16 /30|
|Bartok|0.7702|0.8795|0.2664|0.7584|0→0 /5|
|Beethoven|0.8158|0.9815|0.4316|0.8831|0→0 /0|
|Brahms|0.6462|0.9376|0.1942|0.7349|1→9 /18|

合并所有事件后，参考 4990 个起音，原流程预测 6195 个、匹配 4229 个，专用预测 5005 个、匹配 4766 个。汇总如下：

|指标|原流程|专用模型|

|起音F1，标准50ms|0.7562|0.9537|
|踏板延音区间F1，标准容差|0.2752|0.8216|
|踏板延音区间F1，固定40/80ms|0.3126|0.8160|
|原按键区间F1，标准容差|0.2076|0.3752|
|原按键区间F1，固定40/80ms|0.2764|0.3852|
|≥2秒延音区间匹配，标准容差|23/243|156/243|
|≥2秒延音区间匹配，固定40/80ms|8/243|133/243|

代码中的 `strict` 指固定起音40ms/音尾80ms对照：对长音更严格，但对很短的音，80ms比标准的50ms音尾容差更宽，**不是对所有音都严格的子集**。两套结果都完整保留。逐曲平均与事件合并分数不同，机器报告同时提供二者。

退步也保留：原按键结束的标准区间F1在 Brahms、Chopin、Rachmaninoff、Ravel、Skryabin 上下降，说明踏板模型不能充当手指松键检测器。1317组踏板延音参照中的紧邻同音重弹，两个起音都匹配的数量由913增至1177，但“漏掉后一个起音、前一条仍跨过它”的诊断数量从22增至63。原按键语义下相应诊断为6→8。长音表达能力增强并未消除错误连接；Bartok 的5条长参考区间仍没有一条完整匹配。

先前[合成音和重复和弦反例](piano-offset-research.md)仍有效。本次真实钢琴改善不能支持将专用模型推广到人声、弦乐或全部混音。

## 便携运行与正式应用路径

将原权重导出为固定 batch=1、10秒、opset17 的 ONNX，154214195字节；SHA256为 `7488435a431ba2863de16c56be24f3626dc75e38cc22f3103e193a677494fafa`。模型沿用CC-BY-4.0，作者、来源和修改记录见[模型元数据](../assets/piano-model.json)。应用使用已有 ONNX Runtime CPU，无需新增 Torch 安装。

- 单个10秒窗：7项输出的最大绝对误差不超过约1.33e-5；36个解码事件的最大时间差0.000477ms。
- 全部11首的上游激活送入独立NumPy解码器：6122个事件的音高、力度和浮点起止逐项完全相同。
- 预先选定Bach/Haydn/Skryabin各70秒，真实运行便携的重叠分窗、拼接和解码：共1531个事件，音高/力度相同，最大起止差0.003815ms，取整到毫秒完全相同。
- 原Nova《樱花草》完整钢琴轨运行便携网络，1557个候选。正式 `provided` 导入后逐采样核验与网络输入一致，再通过暖缓存运行 `analyze_deep`，1557个候选均保留。这是暖缓存整合，不冒充再次跑完整网络。
- 真实Flask API用《樱花草》6.664–18.664秒片段完成音频导入、提供钢琴轨、冷分析、暖分析、重开项目、声轨和静态资源读取。冷运行30.75秒、暖运行2.4秒，均为94个候选且结果相同。时间是本机这次运行观测，不是速度承诺。

只有用户明确选择专用钢琴采音，且输入为六声部分离或包含钢琴的自带声轨时启用。缺模型时禁用入口。默认通用流程保持原行为；钢琴专用路径不再叠加通用瞬态融合移动起点。缓存独立，身份包括模型、分离身份、PCM内容、样本数和采样率。

每条候选记录释放回归、持续激活消退、同音高重弹、6秒时长上限或输入边界。后两种未观察到音尾的候选保留原始检测区间，但自动表达和LN选择仅使用起音。专用起音激活用于检测强度，不把演奏力度当作置信分数。

新增/相关11项测试通过；本轮此前全量331项测试通过。前端脚本语法检查通过。浏览器自动化初始化报 `failed to write kernel assets`，未能完成本轮新控件的视觉验证；API核验不替代视觉验证。尚未构建新的发行包。

## 《樱花草》差异诊断

模型只读取作者实际使用的Nova钢琴轨，没有读Reference、红线或书签。固定22.5ms制谱提前量、40ms容差下，828组预测与Reference的808组起音匹配807组，F1为0.9866；不扣提前量为0.8949。若使用已知人工Timing再量化，F1为0.9920，这仅是已知拍线诊断，不是自动Timing成绩。

自动Timing在这次仅提供钢琴轨的应用检查中仍给出296 BPM、Offset 3ms、低置信且不稳定，不能称已经自动找对作者74 BPM/178ms时钟。此结果与声音起音检测分开保存。

Reference钢琴为1038个短键，模型有1557个音高事件。差异可能包含声学误检和作者取舍，不能要求模型机械减到1038。Reference没有物理音高或音尾真值，所以这次也没有测得《樱花草》钢琴音尾准确率或LN完成度。下一步需要结合段落、目标难度及所选声部组织起音组，并检查同音重弹错误连接。
