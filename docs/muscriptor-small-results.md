# MuScriptor small固定输入对照结果

2026-11-11。公开GGUF恢复的small权重已用原Python推理代码完成全部35份
真实输入及40秒静音。八类独奏的汇总起音和完整区间均低于现有Tsumugi，
七份混音两项也全部下降；**不替换默认引擎，不再追加这版模型的Nova整曲
推理或根据这批成绩调参**。该结论限定于本次权重、精度和推理配置。

max(50ms,参考时长20%)，下表为micro F1。28份独奏与7份对应混音共享
七次演奏，训练重叠未排除，不是35首独立歌曲或未知盲测。

## 完整上下文的异常也保留

36个输入共288个5秒块；`transcribe`调用累计1109.908秒，含token观察，
不含模型加载及之后的离线解码重放。静音输出0个音符。

全部40秒上下文共保留6605个原始事件；音尾来源为预测note-off 4765、
同音重弹截断85、输入结束最短时长封口48、鼓最短时长1707。没有把
后面三类封口当作独立释放证据；即使预测note-off也不是已验证的LN放手。

`12-mix`最后一个5秒块生成2000个token，未产生EOS。原协议允许保留
缺EOS块，本轮未将它清空或删掉错误事件。这个输入含25个非正区间、
38个音频范围外起音、1707个鼓最短时长事件，均来自该最后一块；音尾达到或越过音频末尾
39个。另`24-1-vn`和`25-1-vn`各有1个尾达到或超过输入末尾。

上述非正区间、越界起音、鼓事件均不在预先固定的0–30秒评分范围内。
因此评分区间中的这些计数为0，不代表完整输出没有异常。全上下文的
事件、token、强制前缀和封口原因均保留，不能用前30秒的F1掩盖后段问题。
若评分区内有非正预测区间，既有评分器会保留原预测分母、禁止区间匹配。
