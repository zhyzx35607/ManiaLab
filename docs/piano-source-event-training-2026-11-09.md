# 保留持续事件的钢琴局部声部训练

已将核验过的MusicXML持续事件接入可运行的图缓存与训练入口，并实际完成固定四轮适配。原模型与适配模型在完全相同的新图上比较，验证集局部记谱后继宏F1由0.860639升至0.917834，按事先固定规则选epoch1。该指标仅评价有限范围内的记谱连接，不表示歌曲采音、全曲旋律或LN质量已达到交付标准。

输入为此前完成源核验的136份train/validation文件。每谱取前16个有音小节；连续4小节负责监督，前后各1小节提供上下文。每个已确认持续事件只有一个节点，跨小节tie不产生新起音，更早开始但仍持续的事件按区间重叠进入窗口，原起止不裁切。未知、含排除装饰音的小节、缺少身份依据的跨小节连接不作为负例。拍号从原XML读取，弱起长度不冒充正常小节长度。

| 数据范围 | train | validation |
| --- | ---: | ---: |
| 文件 | 127 | 9 |
| 窗口 | 511 | 36 |
| 候选连接 | 1,829,267 | 125,880 |
| 有监督连接 | 167,175 | 8,004 |
| 正例 | 27,362 | 2,218 |
| 有监督谱表节点 | 26,178 | 1,966 |

全部547个缓存通过哈希与监督计数复核。监督连接按目标起音的core唯一归属；carry共93次进入、153次离开窗口，不据此添加起音或结束标签。输入不含staff/voice目标。首次真实模型前向发现float64时间特征与float32网络拼接不兼容，已在网络输入边界转float32，缓存仍保存int64原tick及float64 quarter值；修正后完成有限输出/梯度及标签扰动不变检查。

选中轮在9份验证文件中，局部连接F1为7份上升、1份不变、1份下降；Medtner例下降约0.00765。谱表总正确数下降9，不能把局部连接改善说成全面改善。训练实际耗时约727秒，每轮有一个没有可监督标签的窗口被跳过。全部阈值固定0.5，没有按结果搜索阈值。

独立只读审阅重新遍历136份源表示和547个缓存，核对了几何诱导图、无倒退rest、唯一监督归属、局部正例及unknown/grace屏蔽；没有重新跑模型。另一个公开汇总器从保存结果重算各轮计数、宏F1和选中权重哈希。由于执行协调失误，准备阶段生成了两个不同目录的同内容缓存；保留两份，550个文件逐SHA一致，正式训练只读取`source-event-dataset-v1`。它们不是两组实验。

训练后另用事前已有的六个合成控制检查同一选中轮，没有按控制结果重选权重。原权重与适配权重的局部连接F1如下：

| 控制 | 原权重 | 适配epoch1 |
| --- | ---: | ---: |
| 低音保持 | 1.000000 | 1.000000 |
| 高音保持 | 0.933333 | 1.000000 |
| 双层和弦 | 1.000000 | 1.000000 |
| 交叉旋律 | 0.774194 | 0.714286 |
| 宽音域琶音 | 1.000000 | 1.000000 |
| 模拟踏板重叠 | 0.568421 | 0.000000 |

踏板重叠从TP27/FP40/FN1退步到TP0/FP20/FN28。验证集改善掩盖了重叠音输入的严重退步，因此这组权重不能启用到应用。宽音域琶音的谱表同层成对F1也从0.634146降为0.600000。和弦控制只有双层和弦具备正例，其和弦F1保持1；其余五例没有和弦正例且没有误报，应解释为不适用，而非和弦预测全失败。15个保存产物哈希、12条统计及不读取part标签的输入图由独立审阅重算核验。控制运行见 `scripts/check_piano_source_event_controls.py`，冻结规则见 `piano-source-event-controls-protocol.md`。

这是clean记谱输入适配，合成控制已经暴露踏板重叠退步，真实采音的音尾不确定性尚待验证。和弦head没有监督，但共享编码器发生更新，因此也不能声称和弦输出质量保持。图中未监督的跨小节候选虽有分数，不能直接拼成全曲旋律身份。旧数据集分数与本次新表示的分数口径不同，不能直接相减。
