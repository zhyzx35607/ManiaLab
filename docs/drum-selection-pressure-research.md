# 鼓起音省略的容量诊断

2026-11-09，dev.2测试包冻结之后的研究，不改变默认生成，也不改已发布包。使用上一轮冻结的独立声部表达方案，逐个检查省略的鼓起音若单独加入最终谱面，是否违反原来的密度、和弦或轨道容量。没有读取作者Reference，不以多写note当音乐改善。

新伴奏输入6–10K各留下324个鼓物件；另有202个已经进入表达候选的鼓起音因为整组取舍省略。逐个添加检查结果在五种键数下相同：

|省略起音的情况|数量|
|---|---:|
|单独加入会超过每秒7物件的密度上限|142|
|单独加入不违反当前容量|60|
|上述60个中，起音量化移动不超过30ms|55|

这些检查包含起音后的一秒内其他起音处的滚动窗口，不能只看该拍是否留空。60个“单独可放”不代表它们可以全部一起加入，也不能证明声音真实存在或应该写入。它说明完整节奏组的全选/全弃限制，确实会连带省略局部仍放得下的起音。

与上轮旧表达相比，独立方案新增6个鼓起音、减少36个；减少项均未大幅偏离已给定拍线。其中26个受密度上限限制，10个单独仍可放入。这个36项子集另用完整事件枚举检查，与快速诊断逐项一致，并核验1000ms窗口的排他边界。不能把全部差异解释为对音变差。

下一步应分别研究：密度预算如何在声部间分配，以及节奏组如何提供保留重音、保持重复结构的简化选项。直接填满所有空位会改变难度和表达，也没有解决鼓音色识别，因此本轮只保留诊断，不自动补音。

完整统计、输入和代码哈希见[机器报告](drum-selection-pressure-research.json)。逐起音诊断仅存本地`test-data/sakura-benchmark/drum-selection-pressure-v1`。使用脚本`scripts/audit_drum_selection_pressure.py`可重现固定输入分析；原始声音检测、表达策略、谱面、密度和LN尾端均未修改。此结果不是自动Timing验收，沿用明确给定的74 BPM、Offset178、四细分和22.5ms提前量。
