# 小节边界、延音线与声部身份审计

2026-11-09，在最小例子首次解析和预处理前冻结。仅审计当前固定 Piano_SVSep 与已安装 Partitura 对延音线、书写音符和起音的处理，不读取或改写现有训练缓存，不训练、不修改上游和应用。

怀疑点来自 `remove_ties_acros_barlines`：函数声明只拆跨小节 tie，但末尾检查 `note.end.t != note.tie_prev.start.t`，可能连正常的同小节 tie 也拆掉。缓存准备在调用该函数之后才创建 note array，并未保存它返回的源/目标 ID。因此先用完全自行构造的 MusicXML 区分真实重弹与书写延续，不用新训练分数掩盖数据语义问题。

固定主要例子：同小节两个音的 tie、同小节三音 tie 链、跨小节 tie、无 tie 的同音重弹、同小节跨 staff 的 tie、单音。补充同一 part 内两个 voice 同音高的并行 tie，检查导入器是否能区分，明确其属于导入歧义控制，不把解析后错配当作正确真值。每个音使用唯一显式 ID，原文同时保存声音 tie 与记谱 tied 标签；记录构造时预期的连接和时钟，不引入外部谱面。

每例从同一 XML 独立解析两份：一份不调用拆 tie，一份只调用冻结上游函数。先保存解析后的书写音符、part/staff/voice、原始起止、tie_prev/tie_next 和全局稳定 ID，再分别输出完整 score 的 note array。保存预处理返回的 tie ID，以及执行前后书写音符关系和 note array 的差异。两次独立加载在处理前必须一致；原输入文本、原始 score 分支和上游 tracked source 必须保持不变。每例错误独立记录，不能把异常例子静默删除后宣称通过。

验收只针对数据语义：同小节合法 tie 应保留为持续音，不应产生第二次起音；跨小节 tie 应被明确记录为上游故意拆分的情况；无 tie 的同音重弹不得合并；单音应完全不变。跨 staff 例子若可解析，应保留同音持续，不应仅因谱表变化成为重弹。并行同音 tie 以构造时的期望连接校验解析器，若发现歧义则作为不宜自动信任解析连接的证据。

同时保留 tie 的“同一个音持续”与声部跨小节“后一个新起音属于同旋律”两种关系的区别。当前 `(staff, voice)` 是记谱属性，不自动获得全曲旋律身份；不同小节编号相同不够成为连接真值。tie 也不能直接给出音频里的物理松键或完整乐句边界。

所有生成 XML、逐音符快照、数组及报告保存到新目录 `test-data/piano-svsep/bar-identity-v1`，不覆盖已有输出。记录上游提交、原预处理文件和 Partitura 导入/数组代码哈希、运行器与协议哈希、库版本及生成产物哈希。报告明确哪些期望通过、哪些出现实际反例；本轮不修复旧数据、不改权重、不宣称音乐质量验收。
