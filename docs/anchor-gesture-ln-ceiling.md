# 起音规划的 LN 上限对照

2026-11-09。在首轮结果已被检查后追加的开发实验，不称独立盲测。

首轮同曲后段的完整 LN 匹配提升，但全曲 2291 个输入物件生成了 1223 个 LN，比例 53.4%，明显偏离所给的 34.25% 风格条件。浏览器谱图也显示过多连续持条。仅按校准 F1 选择 logit 偏置并不能保证参数数量符合用户意图。

追加一个明确可选的 LN **上限**：最多 `floor(输入物件数 × 指定比例)` 个 LN。整数规划在该约束下从同一批候选中选择，不删除起音，不剪短已选长条，也不要求必须填满配额。它控制数量上限，不能证明被选长条具有正确的声部归属。

对照使用首轮已经冻结的权重、LN 偏置 1.5、共同放手代价 0，不重新用后段选择参数。保留首轮无限制输出及其失败，不用新结果覆盖旧结果。初次实验报告序列化曾因 NumPy 整数失败，评分已从冻结事件恢复，没有重跑挑选生成结果。
