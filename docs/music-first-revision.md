# 采音与段落表达修订（开发中，2026-11-08）

用户反馈的核心问题成立：alpha.5 没有先规划歌曲每段表现哪些声音。固定 15 秒窗口、逐物件密度竞争和全曲 LN 数量约束，不能代替乐句与声部编排。此前的 7907 份谱面训练主要学习固定起止下的轨道选择，不是乐器转录或采音取舍训练。

2026-11-09源码后续：完整六声轨检查发现复音和弦超容量会导致整组消失，新增保留起音序列的降层选项，并降低主声部偏好压过对音证据的程度。实际6–10K生成、退步记录和剩余问题见[起音组与表达层数](chord-expression-research.md)。该改动不在下述旧开发包中。

## 本次已经落到代码的改变

1. `structure.py` 对混音频谱、能量、逐声部起音与持续活动比较前后 4/8 秒上下文，提出音乐变化边界。计算在半秒特征上完成，候选边界对齐检测拍线。它是声学变化检测，不识别“主歌/副歌”的语义；相似组 S1/S2 也只是统计相似。
2. 可以编辑边界、采用导入谱面的 Bookmarks、查看并保存各段主声部与表达。策略包含持续音、只取起音、人声连续乐句和不采。绿线保留为参考信息，不自动当成分段标签；不生成虚构的 SV/Kiai。
3. `expression.py` 先执行逐段声部策略，再对声部音组做密度/和弦/未来占轨约束，最后定轨。优先完整保留主声部的音组；音组本身超出预算时降至逐起音组。持续音被保留时，保留有依据的音尾，不为全曲 LN 比例单独转成短键。省略原因与音符 ID 一起保存，可在界面定位，全部记录可导出 JSON。
4. 段落快照跟随生成候选。之后修改边界不改变旧候选的导出书签。Bookmarks 从音频时钟换算到谱面时钟一次，严格重定轨继续保留原谱 Editor/TimingPoints。
5. 在分离的贝斯声部上增加一个很保守的低音重复触发检查：MIDI 21–48 的音高激活必须持续存在，窄频波形在疑似新起音前后必须近乎不变，才排除这个重复触发。不会跨激活缺口连接，也不会把音尾延长到已有持续证据之外。混音、人声和其他声部没有启用这个修正。

新分段模式中，“持续声部倾向”影响自动声部方案，不保证导出 LN 数量比例；手工保存声部方案后，以逐段设置为准。旧项目在尚未检测音乐段落时保留原选择流程，点击“检测音乐段落”可迁移，不必重新运行音高网络。若要获得贝斯修正，则需要重新分析；模型激活缓存仍可复用。

## 开发包的检查顺序

1. 打开旧项目，点击“检测音乐段落”；新分析自动执行。先确认 BPM / Offset，再逐段定位试听。可编辑分界秒数，或采用导入原谱的书签。
2. 展开各段，在单声部试听中确认声音。选择主声部，并明确每个声部“持续音用 LN”“只表示起音”“本段不采”；人声另有“连续乐句”，需要回听其支撑区间。保存方案后再生成。
3. 先检查主声部的起止、漏音、误音，再看混合结果。若检测证据本身断碎，提高密度或持续倾向无法修复。低密度和占轨预算也仍会省略音组，记录会说明原因。
4. 在省音记录里定位可疑位置，下载分析 JSON 可查看全部候选的决定及当前生成结果使用的段落快照。不要把自动建议的 S1/S2 当成主副歌名称。

## 对用户谱的检查

本地固定版本《童话》10K（BeatmapID 5848413）有 9 个书签：14.273、42.508、70.744、95.450、109.567、137.803、166.038、194.273、226.038 秒。两条绿线在 194.273 / 226.037 秒，SV 均为 -100，分别打开、关闭 Kiai。这些信息符合“先划分结构，再安排表达”的创作过程；不能据绿线数量推断所有段落。

另检查用户《九万字》（5877693）完整音源：自动声学分段与部分书签/Kiai 边界接近，也漏掉了多处人工段落。故提供编辑和直接采用原谱书签，没有把自动分段包装成准确的主副歌识别。

## 验证与尚未解决的问题

独立合成声部测试包含已知的 64 个贝斯音、42 个旋律音、24 个和弦音。音高完全相同、起点误差不超过 40ms、终点误差不超过 80ms，使用一对一匹配。贝斯完整区间匹配从 31/64 到 57/64；预测数由 98 到 67。旋律和和弦结果未变化。另有 24 组低音重复和弦反例，包含 10/30/80ms 真正停顿及干扰持续音；没有新增长音误连或减少匹配到的真起音。这些是合成诊断，不是自然贝斯、人声或所有音色的准确率。

《有点甜》重新运行已有六声部缓存后，低音规则排除了 116 个重复触发候选，最终原始候选从 6809 到 6703；数量变化不是准确率。《有点甜》和用户《九万字》均完成新旧选择对照、定轨与回读检查。新的主声部策略避免了 LN 配额导致的长转短，并保留更多人声候选；但是人声检测仍有大量短碎区间，不能据此宣称“人声 LN 已经写好”。自动方案也可能选错主声部，逐段声部属于待试听的建议。

实际 Edge 页面验证了编辑边界、保存声部表达、重新生成、保存后重开、书签时间换算和窄屏布局。工程测试通过仅表示这些路径可用，不能代表音乐质量。

配对音频训练结果见 `music-first-validation.json`。首个完整基线使用 62 首与核验谱面一致的音频，46 首训练、16 首按歌曲留出，259698 个候选，包含 35 首短键为主、26 首 Hybrid、1 首 LN 为主。文件不同仅允许逐字节核验后的 LF/CRLF 等价，其他修订不冒充匹配样本。模型输入声部、激活、音高、持续长度、局部密度和节拍位置；标签只是与人工取舍匹配，不是全部声音真值，也没有人工乐器归属标签。

初始起音 AUC 从激活强度基线 0.59984 到 0.84195，但去掉节拍特征后只到 0.61665；很大部分收益来自节拍位置。初始持续音 AUC 0.85988，低于长度基线 0.87259，去拍特征后为 0.83303。此结论与此前 `preference-research.md` 的相位敏感问题一致；不能拿高起音分数声称已经理解音色。

随后完成新增 10 首配对音频：6/7/8/9/10K 各一首 LN 和一首 Hybrid，分析每首 60 秒片段，匹配时排除首尾各 3 秒。最终共 **72 份谱面、71 个歌曲组、272237 个采音候选**，保留 35 份短键、31 份 Hybrid、6 份 LN；没有 LN≥50% 的全局筛选条件。按歌曲身份与原音频 SHA256 并查集分组后，53 份训练、19 份留出，同曲不同难度不跨组。

最终协议将持续音评价限定为音高检测中 ≥100ms 的区间，排除了仅靠区分鼓与音高取得分数的捷径；这与初始 62 首的持续音评价范围不同，不能直接把两次分数当作性能变化。最终结果：

|取舍标签|完整模型 AUC|无拍位特征 AUC|简单基线 AUC|
|---|---:|---:|---:|
|人工谱面的起音位置|0.85259|0.61736|0.59723（激活强度）|
|人工谱面的完整持续区间|0.71186|0.62029|0.76400（持续长度）|

这些是按留出谱面平均的弱标签排序分数，不是自然乐器转录准确率。起音仍依赖拍位，持续音仍未超过基线，因此**新权重没有进入应用或发行包**。当前训练器是采音候选取舍的小型研究模型，没有重新训练分离网络或 Basic Pitch，更没有学出人工乐器归属。

真正仍需要解决的是：自然声音的漏音、误检、重复发声与滑音区分、不同乐器同音高重叠、混响与有效音尾区分，以及基于乐句的主次取舍。当前四/六声部分离不等于识别任意音色，也不能保证单独播放任一乐器就采出所有音。没有针对这些问题的听辨真值，就不能用 Ranked/Loved 谱面作为“完整转录答案”。

## 本轮参考

- Spotify `basic-pitch` 官方 README 和 `note_creation.py`：乐器无关的多音高转录、单乐器输入限制、起音/持续激活后处理。没有复制其 Melodia 回收作为默认补音，以免把串音当新音。
- osu! wiki `Guides/osu!mania_mapping_guide/en.md`：同类声音表达的一致性；`Client/File_formats/osu_(file_format)/en.md`：Bookmarks 与 inherited timing points 的含义。
- `mir-aidj/all-in-one` 官方 README：主歌/副歌语义分段是独立的模型任务。当前实现没有安装或冒称使用该模型。
- `krrcream/krrcream-Toolkit` 固定 commit `42a343a0353abf10d5f01c7088081440a007372a`，阅读 `Tools/KRRLNTransformer/KRRLN.cs`：从既有谱面的时间矩阵、可用空间和选项变换 LN。它没有提供本项目缺少的音频持续真值，未把转换逻辑用于采音。
