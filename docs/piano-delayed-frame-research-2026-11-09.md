# 延迟持续激活：真实录音收益不足以启用

固定起音后等待最多50ms、且要求至少连续两帧持续激活的研究规则，已在11份既有自然钢琴录音上完成验证。结果没有足够收益支持接入应用：踏板延音标准区间匹配只从4106增至4107，按键结束标准匹配从1875降至1874。起音、音高、力度及事件数量完全不变。本轮不修改正式解码器、不发行新权重。

复用已核验的70秒模型激活，仍只评分前60秒起音。全部6122个录音候选中提出21处音尾变化，其中16处在评分窗口；《樱花草》1557候选另有15处建议，因缺少音尾真值，不算作15处修正成功。没有重新跑网络、调整阈值、按歌曲选择规则或使用Reference/拍线决定结束位置。

| 区间匹配 | 原输出 | 建议输出 |
| --- | ---: | ---: |
| 踏板延音，标准容差 | 4106 | 4107 |
| 踏板延音，固定40/80ms | 4078 | 4080 |
| 按键结束，标准容差 | 1875 | 1874 |
| 按键结束，固定40/80ms | 1925 | 1925 |

四项的共同参考/预测分母为4990/5005。标准容差为起音50ms、音尾max(50ms,20%参考时长)；固定40/80ms对短音未必更严格。起音标准匹配均为4766。超过2秒参考的匹配数没有变化。

逐曲变化：Brahms的踏板延音在两套容差下各增1；Bartok仅固定40/80ms的按键和踏板各增1；Rachmaninoff的按键在两套容差下各减1。其余曲子计数不变，不能把合并不变解释成各曲都无退步。完整逐曲计数见同名JSON。

独立逐事件检查发现，16个评分内改动有12个在标签中连同音高且±50ms的起音邻居都没有，延长音尾不能解决这些起音/音高偏差。Brahms的一例由5.32秒延至5.87秒，更接近踏板真尾5.889583秒，却离按键真尾5.494792秒更远；Rachmaninoff的一例从28.71秒延至28.90秒，反而破坏了原先接近28.719792秒的按键尾。不能统一把延长解释为“修好了短音”。

实际实现比初始协议一句“回落或者offset峰”更保守：必须先观察到持续激活回落，再允许从该活跃区间内选符合原规则的offset峰。若没有回落，即使出现offset峰也不延长；初始执行协议快照保持原文，不回写为事先规则。另一个报告字段 `existing_active_tail` 只是“本规则未处理的非frame_inactive候选”，其中也包含重弹/输入边界等强制结束，不能据名字断言音尾确实已观察到。

27项构造控制通过，覆盖孤立尖峰、早offset、同音重弹、不同音高、50ms/6秒/输入边界、亚帧起音、不可变输入及空输入。17个本地产物的SHA256已核验。诊断脚本为 `scripts/piano_delayed_frames.py`，重放与评分入口为 `scripts/check_piano_delayed_frames.py`；原始逐事件结果留在 `test-data/piano-delayed-frames-v1`。

这次分析支持继续把“检测到了起音但持续不明确”作为可见的不确定证据。它没有证明应该统一拉长这些音，更没有把物理延音当作制谱LN放手。
