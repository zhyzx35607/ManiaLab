# 跨窗口起音与歌曲开头的区别

2026-11-10。Tsumugi 的一个区间可以表示窗口开始前就已经持续的声音。
这样的左边界不是新起音。先前候选桥接保留了该区间，却没有检查起音来源，
会把它送入编排并可能变成新的 LN。单看最终 `has_onset` 也不够：上游拼接会
对标志做 OR，后一个片段的正标志不一定支持合并后的最早起点。

现在逐一追溯最终 `start_sample` 所对应的原构造：有明确 boundary head
起音、且起点没有裁切，才作为模型预测的 attack。保留原始采样时间，
不把它挪到拍线来掩盖来源问题，也不借用其他音高、slot 或更晚起点的证据。

原音频第一个窗口、第 0 帧已经活动的区间有专门处理：只在存在 boundary
head、起点未裁切时保留，标记 `input_start_active_interval`。它可能是开头音，
也可能是裁切前已发声的持续音，不能称为观测到起音。内部窗口没有此例外。
被排除的区间仍在原预测和逐音 trace 中；起音检查不修改音高或音尾。
模型尾仍需单独开启，并通过已有端点来源检查，才能作为 LN 时长候选。

## 全部固定输入复核

纯重放 156 份已完成输入：35 URMP、17 bass、60 GuitarSet、40 vocadito、
4 个《樱花草》全曲声部；其中 152 份有逐音标注，包含 192 组独立标注。
没有重新推理或改动原音频、原预测。所有保存构造、窗口和最终输出均与
固定上游代码重放一致；原基线匹配计数与已冻结报告一致。

18,455 个原始事件里有 123 个没有起音预测：63 个属于原输入开头，60 个
来自内部窗口。此队列没有实际发生 fallback、起点裁切或后段 OR 冒充前段
起音；这些代码路径另以回归案例检查，不能说它们已在歌曲中实际出现。

如果全部删除未观测起音，会损失 7 个贝斯和 51 个吉他开头音的标准起音
匹配。加入输入开头例外后，重新匹配结果如下；负数表示相对保留全部原始
事件的减少。所有类别仍参与原评分，不按已知乐器标签删掉错误类别。

| 输入 | 起音 ΔTP／ΔFP（50 ms） | 起音 ΔTP／ΔFP（40 ms） |
|---|---:|---:|
| URMP | 0／−4 | 0／−4 |
| 贝斯 | 0／−2 | 0／−2 |
| GuitarSet | −1／−2 | −1／−2 |
| vocadito A1 | −1／−3 | −1／−3 |
| vocadito A2 | −1／−3 | −1／−3 |

URMP 第 5 个被排除事件在固定 30 秒评分窗外。吉他和人声各有一个内部真音
匹配损失；这两个模型继续不替换应用默认。输入开头例外也保留了原有的
4 个误报，不能将它理解为准确性保证。完整区间的标准协议中，吉他为
0 TP／−3 FP，其余变化同表；40/80 ms 区间协议的变化同表。

《樱花草》保留 other 的 1 个开头活动区间，排除 other 的 42 个内部区间、
vocals 的 4 个内部区间。没有独立逐音真值，不能说排除 46 个就修好了 46 个
错音。原导出的 141 个 other 大幅量化移动中，8 个来自未观测起音；另外
133 个仍有模型起音支持，无法用此修复或统一 Offset 调整解释。

复核入口：`scripts/audit_tsumugi_onsets.py`。本地完整证据及逐例匹配保存在
`test-data/tsumugi-onset-provenance-v3/`；音源和原谱不随公开仓库发布。
公开测试数据可能被模型训练见过，URMP 单轨与混合输入也会复用演奏。
这些结果说明来源策略的实际损益，不是听感、自动 Timing 或 LN 音乐验收。
