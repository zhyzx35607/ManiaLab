# 声部分组上下文：观察关系与归一化的独立对照

2026-11-09。固定权重的四组对照已确认：在本次 64 个 validation case 和两套《樱花草》预测中，**同时移除跨窗观察边、按窗口计算 GraphNorm，可以复现真正逐窗推理的分类与最终连通关系。** 《樱花草》适配组件表达对归一化范围尤其敏感，但观察关系也有影响，二者会相互作用。这个结论用于定位不稳定来源，不代表换一种归一化就能得到好的 LN，更未解决跨小节乐句。

本轮承接[rest 构图修复](piano-stream-context-research-2026-11-09.md)，按[预先固定协议](piano-stream-context-factors-protocol.md)执行。运行耗时 52.875 秒；没有重训、调概率门槛、重新采音或调整 Timing。16 份 validation 的 clean/whole、原模型原候选和 epoch 5 适配扩候选保持不变，不读取 test 数组。

## 四组实际比较

所有组先修复错误 rest，并保留同一完整输入的全部节点、特征、候选边和官方后处理入口。观察边的反向关系仍由官方推理创建；GraphNorm 通过临时前钩子传入窗口分组，执行后移除钩子，源码和权重未改。

|标识|观察关系|GraphNorm 范围|
|---|---|---|
|`full_global`|完整图|全部节点|
|`cut_global`|去掉跨窗边|全部节点|
|`full_window`|完整图|按四小节窗口|
|`cut_window`|去掉跨窗边|按四小节窗口|

`full_global` 逐数组复现上一轮修复后的完整图预测。`cut_window` 与真实逐窗预测按候选边键对齐，所有 case 的三个输出头都在预定 `atol=1e-4, rtol=1e-5` 内一致；实际最大绝对差分别为 voice logits `5.72e-6`、chord logits `1.37e-6`、staff 分数 `7.45e-7`。staff 分类、最终 voice/chord 边与同小节连通关系均无残差，《樱花草》表达也无残差。这是已测输入的结果，不保证任意新输入都能达到相同浮点与后处理一致性。

## 《樱花草》的 141 次翻转不是同一批音

相对 `full_global`，适配模型按 components 表达有以下变化。统计对象是通过既定强度/段落筛选的 1532 个钢琴候选；它们还没有经过选音和定轨。

|变化|长变短|短变长|总翻转|表达长条数|
|---|---:|---:|---:|---:|
|只去跨窗边 `cut_global`|19|12|31|523|
|只按窗归一化 `full_window`|62|79|141|547|
|两项同时改变 `cut_window`|67|74|141|537|

基线为 530 个表达长条。“只改归一化”与“两项同时改”虽然都是 141 次翻转，交集却只有 125 个候选，双方各有 16 个不同，合计 32 个候选的结果不同。不能把它们当成同一批音，也不能将 31 与 141 相加来解释总效果。

只切边与只改归一化的翻转集合交集为 13，合集为 159。两项同时改变时，有 12 个候选在任一单独改动中都未翻转，另有 30 个单独改动会翻转的候选在组合后恢复基线。表达结果确实有交互，不能归结成一个单独因素的固定贡献。

按 staff 表达也有差异：适配模型只切边翻转 9 个，只改归一化 28 个，两项同时改 30 个。原模型 components 在四组下都保持 1377 个表达长条且没有长短翻转，但其原始连接输出仍变化；表达规则饱和不能被误读为声部模型稳定或音乐正确。

## 对已有输出的补充统计

首轮推理保存了四组预测和表达，但报告只列总翻转，未直接列交互量及双向翻转。此次汇总从固定 NPZ 按候选边键对齐，以 float64 计算

`interaction = full_global - cut_global - full_window + cut_window`

它是模型输出的差分之差，不是统计显著性检验。voice/chord 使用原始 logits，staff 使用带 Sigmoid 的分类分数；分别报告最大、平均绝对值与有符号均值，不跨输出头混加。

|《樱花草》适配输出|最大绝对交互|平均绝对交互|
|---|---:|---:|
|voice logits|2.80240|0.08044|
|chord logits|1.22334|0.01286|
|staff 分数|0.57389|0.00581|

同样对最终 hold/tap 的 0/1 值计算差分之差，适配 components 有 55 个候选为非零，其中 29 个为 -1、26 个为 +1。这与简单相加翻转次数是不同统计。上述连续交互量、双向变化和集合交并均为推理完成后的补充汇总，没有改变模型、阈值、候选、上下文或任何表达规则。

汇总脚本核验执行快照、辅助脚本快照、输入/权重身份、rest 基线，以及 factors 的 285 个产物和 rest 的 152 个产物 SHA256；重新核算分数和残差。逐边交互数组及含 ID 的翻转集合仅保存于 `test-data/piano-svsep/context-factors-supplement-v1`；公开 JSON 只含汇总、逐曲统计和身份。

## 对下一步的含义

观察图与 GraphNorm 范围足以复现本批输入的窗口差异，说明不能随意改变推理窗口后仍把组件当成稳定旋律身份。仍需解决的是：某条声部在小节边界后是否继续、真实停顿在哪里、延音证据是否可靠，以及后续声部怎样分配给可演奏的 LN。当前组件的候选连接局限于小节；即使某个组合分数更高，也不会自动获得跨小节身份。

本轮未启用应用默认、未发布新模型、未重跑成谱导出。用户的参考谱继续只作为声部分工和表达思路参考，允许错漏，不作为强制复刻标签。

使用 `.venv/Scripts/python.exe scripts/summarize_piano_stream_factors.py --supplement <新本地目录> --output <新JSON路径>` 可重做身份核验和汇总。脚本读取已保存预测，不执行模型；补充输出不覆盖原实验。
