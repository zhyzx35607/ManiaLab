# 钢琴重弹截尾与 LN 放手的边界

2026-11-10。Kong 钢琴解码器把前音在下一次同音高起音的前一帧截断，并明确给出 `release_reason='reattack'`、`release_observed=False`。这个结束位置可以保存、审查和评分，但没有独立证据说明在该处观察到了放音。

此前 `PianoDetector` 将事件转为 `Note` 时保留 `release_reason`，没有 `release_observed` 字段。统一的 `UNOBSERVED_RELEASES` 列表遗漏裸 `reattack`，因此表达层和全局 LN 选择会放行这个截尾。其区间还被计入 `observed_interval_coverage`，并可延续到后续段落的活动统计。

本次只把**裸 `reattack`** 纳入未观测放手集合。起音、原始音高、候选音尾、网络激活和物理区间评分均不改变；自动方案及手动 `sustain` 仍须经过同一证据保护，不能靠选择持续表达把未知尾升级为可靠放手。已经生成的旧谱面不自动重写。

## 不混淆两种来源

| 来源 | 规则 | 本次处理 |
|---|---|---|
| Kong `reattack` | 下一次同音起音前一帧强制封口，事件明确 `release_observed=False` | 保留原始候选，表达为短键 |
| Basic Pitch `same_pitch_reattack` | 到达下一个已接受的同音高起音 | 保留既有音乐边界策略及 LN 资格 |
| `frame_decay` / `release_regression` | 已有持续回落或回归尾证据 | 保留既有资格，不宣称物理松键真值 |

Basic Pitch 的选择已明确记在 [通用采音音尾来源](basic-pitch-release-provenance.md)：“保留原有资格；不是检测到独立停音”。此次不重新设计这项策略，也不把所有带“重弹”含义的标签一概禁止。若后续允许用重弹时刻创作放手，应增加明确的表达选择与来源说明，不能把它标成观测到的声学结束。

## 调用链与可复现结果

代码路径是 `piano.decode` → `PianoDetector.analyze` → `audio.analyze_deep` → `Note` → `expression_evidence` → `select_expression` → 导出；无分段的旧路径使用 `choose_holds`。两种选择都依赖统一的 `UNOBSERVED_RELEASES`。段落活动、连续起音策略和建议统计也使用这个集合。

构造两个相同音高的起音，时间为 1 秒和 3 秒，持续激活到 5 秒。作者既有解码给出：

- 第一音 1000–2990 ms，`reattack`，没有观测放手。
- 第二音 3000–4980 ms，`release_regression`，有现有模型尾证据。

修复前，真实 Flask `/generate` 与 `.osu` 导出把第一音写成 1000–3000 ms LN。修复后，同一证据与 120 BPM 四分拍分割导出 **1000 ms 短键、3000–5000 ms LN**。两个起音完整保留，原候选仍保存 2990／4980 ms 音尾。自动方案与手动 `sustain` 都经过此检查。

第一音在 `[1000,3000)` ms 内的旧活动统计为 `observed_interval_coverage=0.995`、`uncertain_tails=0`；修复后为 0 和 1，起音活动窗口仍为 0.125。它不再凭未观测尾在后续段落伪装成持续声部。

旧 `test_piano_runtime.py` 已验证重弹事件的 `release_observed=False`，但自动 LN 保护用例没有包含 `reattack`；本次补入，并新增专门测试覆盖实际解码、Note 转换、两条选择路径、活动统计、可靠尾、Basic Pitch 兼容及真实 Flask 导出。

## 旧项目与缓存

神经激活缓存无需失效；旧分析已经保存 `release_reason`，下次生成时即可执行新的保护。自动表达方案会重新提案，手动表达模式也不能越过音尾保护。已生成版本保留原样。

旧手动方案中保存的活动摘要可能仍是旧统计，重新生成自动方案可刷新；现有参数或建议的取舍也可能沿用之前选择。本修复不擅自重置用户模式、重写旧谱或启动音频分析。它纠正证据语义与选择资格，不证明音频模型已经准确，也不改变 HF 独立研究对所有物理事件的完整评分。
