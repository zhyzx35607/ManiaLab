# 《樱花草》声部采音与表达诊断

2026-11-08–09。当前没有达到作者 Reference 与成品 10K 的效果标准。这一轮没有启用新默认权重，也没有发布新 Release。

## 作者确认的监督范围

作者 zhyzx35607 确认谱包中六个声轨是制作 Reference 时实际使用的 Nova 输出。Reference 第 1 列主要为 kick，第 2/3 列为 snare（允许双押），第 4 列主要为 hi-hat，也有 tom 等例外；第 5/6 列为钢琴，双 note 表达层叠；第 7–10 列为其他伴奏，包括提琴。Reference 不采人声。

谱包 2644803，Reference 5969640，成品 Our Everlasting Spring 5969639。镜像压缩包的两份谱面逐字节 MD5 与抓取的官方元数据一致；Reference 有 2340 个物件、199 个 LN，成品有 2806 个物件、961 个 LN。归档、谱面和声轨身份见 [机器可读报告](sakura-source-research.json)。该谱包当前为 pending，实验没有将它伪称为 Ranked。

这些标签是作者的采音取舍，不是完整 MIDI 转录。钢琴列都是短键，因此没有钢琴音尾真值；snare 双押合并为一个鼓类事件，但保留谱面物件数。其他列的输入由 other/bass/guitar 合成，不把它冒称为纯提琴。声轨来自作者 Nova，不能据此声称应用内的公开 Demucs 分离已经达到相同效果。

## 钢琴：起音、音高数、制谱层数是三件事

完整 283.84 秒作者 Nova 钢琴，Reference 有 808 组起音。先报告原始检测，再统一扣除预先指定的 22.5ms 制谱提前量，不用人工拍线吸附评分：

|算法|原始起音组 F1|扣除 22.5ms 后 F1|扣除后匹配起音|扣除后平均绝对误差|
|---|---:|---:|---:|---:|
|现有 Basic Pitch 路径|0.5039|0.8820|744/808|17.24ms|
|钢琴起音/音尾 CRNN|0.8873|0.9890|807/808|10.14ms|

单独提供作者已知红线并按四细分聚合，起音组 F1 分别为 0.9890 和 0.9920。这是已知 Timing 条件下的诊断，不是自动 BPM/Offset 验收。CRNN 的出处、检查点和此前失败样例见 [钢琴模型研究](piano-offset-research.md)；不能用这首歌替代那些反例，也不能拿短键真值评价音尾。

同一组钢琴起音可能检测出多个 MIDI pitch，但作者只选择一层或两层。使用前段音频特征与音高统计学习层数，阈值只在中段校准；后段正确层数比例约 80%，仍有明显差距。后段物件数一对一匹配 F1：Basic Pitch 候选加学习层数 0.9038，CRNN 候选加学习层数 0.9117。后者直接按音高数至少两个就双押只有 0.8774。这个学习结果不默认启用。

## 鼓：类别不能由瞬态数量代替

原检测在全曲得到 1387 个鼓候选；与 562 组作者鼓起音匹配时，召回 0.9929，但精确率仅 0.4023。起音多不代表采得完整而清晰。

一个局部音色分类实验仅读取鼓的频谱和起音变化，不读取绝对时间、拍位或谱面密度。按作者标注合并 snare 双押后，在同曲后段得到 kick F1 0.9555、snare 0.9286、hi-hat 0.3814。hi-hat 仍差，tom 等例外也未明确标注，不能把未标音全视为噪音。拟合区间为 0–162340ms，阈值校准 162340–188286ms，后段 188286ms 以后；重复乐段仍可能造成相关性，这不是独立歌曲泛化。

额外运行了 ADTOF-pytorch 的冻结五类鼓模型，源码固定为 `85c192e78f716ea0b111cc8a5ee4a8f6a3a4f8a9`，权重严格完整加载。后段 kick/snare/第 4 列的 F1 分别为 0.9600、0.8675、0.1667。把其激活作为局部分类器的附加特征，得到 0.9766、0.8764、0.0896；整体未通过，不进入默认流程。第 4 列与模型 cymbal 类反而更接近，只能说明音色标签、作者取舍和模型识别存在歧义，不能据此改写作者对第 4 列的说明。此项目副本未找到 LICENSE，没有向产品复制其源码或分发权重。

## 已有 Nova 声轨的真实应用流程

新增导入已有声轨、逐声部试听和分析的功能，见 [使用方法](provided-stems.md)。全曲测试直接走应用的 `analyze_deep`，没有给作者 BPM、Offset、书签或音符。音轨始终保留原始时间轴；导入失败、取消和切换文件不覆盖旧结果。

该测试依然暴露了采音取舍问题：鼓起音组 F1 0.5791、钢琴 0.8815、其他合并声部 0.1976。尤其其他声部候选太多；不能把“召回较多声音”当作“采音清晰”。默认自动声部方案也可能选择人声，与作者无人声 Reference 的目标不同，比较时必须区分检测和编排意图。

全曲 Timing 另发现一个确定的计分错误：三细分候选从其无法表示的半拍起音获得了奖励。修复后，同样的声学起音从 148 BPM 三细分改选四细分，鼓起音覆盖率 0.7659→0.8629。使用固定 22.5ms 制谱提前量，对作者音符端点的网格残差第 95 百分位从约 63ms 降到 5.51ms。前奏证据仍不稳定，自动生成确认门槛保持不变。

固定旧版代码与修复版分别重算 67 首已有开发样本，以及《樱花草》的冻结起音；9 首改变网格，均未降低对作者端点的 15ms 覆盖率。通过现有稳定性门槛的数量从 18 到 19。这里没有重新运行音频模型，也没有证明人工谱是物理音频时间的完整真值，详见 [网格回归](timing-grid-support-validation.json)。新增测试同时覆盖直拍半拍和真实三连音，避免用偏向四细分的规则掩盖错误。

## 真实声部微调：保留失败结果

直接使用上游编码器、事件解析器与解码器，训练 442368 个 decoder attention LoRA 参数，96 步。三个任务分别是鼓声→Reference 1–4 列、钢琴→5–6 列、other/bass/guitar→7–10 列。没有把整张成品强行配给每个单独声部，也没有凭空添加钢琴音尾。

训练窗口全部位于 0–149367ms；验证窗口连同音频和音符前文全部位于 188286–283840ms。实际采样 30 个训练窗、27 个验证窗。已知整张声部谱的难度、LN 比例作为诊断条件，仍不构成端到端系统。后段与前段属于同曲，重复乐句可能重合。

给定真实前文时，轨道 token 预测从 0.6205 升到 0.7599；但这不能说明自由生成已经学会声部归属。固定后段 215.853–227.853 秒，双方同音频、Timing、条件与随机种子：

|声部|起音组 F1 原→微调|同起音物件数 F1 原→微调|起音+来源列 F1 原→微调|完整 LN F1 原→微调|
|---|---|---|---|---|
|鼓|0.9143→0.9412|0.9062→0.8889|0.1562→0.1880|无人工 LN|
|钢琴|0.8312→0.8750|0.7292→0.7500|0.1250→0.2308|无人工 LN|
|其他|0.7778→0.7317|0.7536→0.8101|0.2609→0.3038|0.5000→0.3721|

结论：拒绝将这批权重设为默认。少量声部训练没有解决音色归属；其他声部的持续表达退步。原模型本来输出演奏布局，来源列匹配是新声部任务的诊断，不能据此评价原模型演奏布局是否正确。

## 从可靠草稿学习成品表达

全曲 961 个成品 LN 中，870 个的两端都在 30ms 内有 Reference 起音事件，704 个参与两个或更多 LN 的共同放手。相同时间常有多个乐器，无法仅靠重合就断言某根成品 LN 属于钢琴或提琴；脚本保留多来源歧义，不伪造单乐器真值。

首次尝试传 `GD` 草稿时发现：固定 mania tokenizer 只有 timing/map/sv 输入标记，上游会选择其支持的模板而丢弃 GD。旧推理产物已明确标成无效实验；训练原始报错也保留。这不是“有了正确草稿模型仍不会写”的有效证据。

新增显式实验编码 `map-delimited-sketch-v1`：在输出 MAP 前用已有 MAP 分隔标记容纳输入草稿，不改变事件 ID 或 embedding 大小。它是新训练任务，并非原权重原生支持。输入不加损失，只有成品目标参与损失；输入草稿不反过来成为目标；草稿去除书签与 Kiai 标记。运行时强制选用包含草稿的模板，并在解析到实际草稿事件后记录日志；缺少该证据则拒绝返回成功。

真实上游解析器/tokenizer 的集成检查证明：改变草稿会改变解码输入，目标标签保持不变，草稿本身没有标签，输入谱不会进入反向训练任务。96 步表达微调后，给定真实前文的时间预测改善，但后段 215.853–227.853 秒自由生成最终为空谱。相同条件的原模型匹配了 46/48 组起音，却仅匹配 4/57 根完整 LN；完整 LN F1 为 0.1026。两者都未达到成品标准。

私有解码记录显示微调模型先输出缺少时间的半个事件，随后跳到被 lookahead 截断的后半窗口。首次增加冷启动训练时，又发现上游 `get_groups()` 没把 `hold_note_sustain` 当作分隔符，导致窗口外长条状态混入后续短键。该次训练已经停止并记录无效；修复后额外冷启动窗口会删除没有条头的 sustain/tail，原有前文窗口保持逐张量一致。

修正后的 128 步实验使用 15 个前文训练窗、15 个冷启动训练窗，以及各 5 个验证窗。真实推理前缀与训练冷启动前缀的集成检查通过，给定前文的 LN 时间预测也改善，但自由生成依然为空谱。因此缺少冷启动样本不是已经证实的唯一原因，该权重继续拒绝默认启用。

进一步比较基线、未合并 LoRA 和合并 LoRA，在两个训练与两个验证冷启动窗口中，完整 teacher-forced 输入与截到首事件之前的输入所得 logits 一致到 0.001 以内。没有在这些检查中发现因果注意力泄漏或权重合并导致的前缀差异。另对真实歌曲的全部 20 个冷启动窗口，分别使用原始草稿与应用包装后的草稿建立推理前缀，40 次都与训练输入完全一致；模板的 OD 差异没有在这些条件下改变输入 token。

在 cold-v2 上继续 32 步，只把冷启动窗口首个完整事件的损失权重提高到 32，其余事件仍参与训练。固定后段 215.853–227.853 秒，除适配器身份外的推理条件与原模型基线一致，结果如下：

|指标|原模型|首事件加权微调|
|---|---:|---:|
|匹配成品起音组|46/48|48/48|
|预测起音组|53|55|
|匹配放手时间组|6/31|24/31|
|完整 LN 起止匹配|4/57|13/57|
|完整 LN 匹配 F1|0.1026|0.2626|

空谱问题在这个片段中得到改善，但输出仍有一处同轨重叠以及未闭合 LN 警告。原始结果没有事后修轨以掩盖问题，权重不默认启用。这是同曲后段、给定作者草稿和 Timing 的表达诊断，尚不证明实际自动采音或独立歌曲上的质量。需要继续检查跨窗口持条状态和更多片段。

另一个后段 241.798–253.798 秒，首事件加权微调匹配成品起音 47/50 组、放手 22/33 组、完整 LN 15/60 根；完整 LN F1 为 0.2542。原始输出仍有一处同轨重叠和 18 条未闭合 LN 警告。这个片段没有配套原模型基线，不声称它相对原模型改善。

### 事件状态约束：语法检查通过，音乐实验失败

新增显式 `--state-constraints` 实验，按此前**生成的输出**维护持条状态，不把输入草稿的列当作持条状态。约束完整事件、轨道范围、同时间重复按键、覆盖未放开的同轨长条，以及无条头放手；不补尾、不事后换轨，时间和结束点仍由模型预测。上游文件保持固定，功能默认关闭。

第一轮在最后一个窗口遇到没有合法后续 token 的死路，未生成可评分谱面。随后避免选择所有列都不可用的时间点，并用与上游 `_encode` 相同的 10ms 量化转换已有历史，防止解码时的 +5ms 中点补偿让重复事件逃过检查。20 个真实冷启动目标、20372 个 token 均通过语法兼容检查。

然而同样的 215.853–227.853 秒实际生成只有 1 根 LN，完整 LN 匹配为 0，仍有一处拍线吸附后的同轨重叠。起音匹配 47/48 组、放手仅 1/31 组；没有未闭合警告不能算作改善。与未加约束的同一适配器相比，这个实验**失败，拒绝启用**。原始失败日志、代码快照、解码 token 和输出都保留在本地。

## 多乐器采音实验：YourMT3

使用作者的 [CPU Space](https://huggingface.co/spaces/mimbres/YourMT3-cpu) 与 [论文](https://arxiv.org/abs/2407.04822)，源码固定 `bd69fbac7da881df0dfb67d8f4068a3d473df347`，模型 SHA256 为 `ae38e415c79efd5592dcb9b658cdb99ddb11d4c4e1eaa364cab04a052473fc25`。严格完整加载检查点实际配置，使用作者的 13 通道事件解码和跨段合并。隔离环境不改变应用依赖，所有音频都在本机处理。

输入只有确认过的 Nova 声轨。其他伴奏使用 other、bass、guitar 原幅度相加；鼓和钢琴各自单独输入。模型没有接收作者红线、书签或音符。起音评分统一使用已声明的 22.5ms 制谱提前量、40ms 容差，不对预测吸附拍线。Reference 是作者的采音与层数选择，不是完整 MIDI 真值；多检测到一个音高不等于需要多放一个 note。

最初 215.853–227.853 秒的起音组 F1：其他伴奏 0.5217、鼓 0.9206、钢琴 0.9655。继续运行完整 283.84 秒，结果如下：

|声部|现有应用起音组 F1|YourMT3 起音组 F1|匹配 / 作者起音组|模型提出起音组|
|---|---:|---:|---:|---:|
|其他伴奏|0.1976|0.7533|316 / 347|492|
|鼓|0.5791|0.7803|412 / 562|494|
|钢琴|0.8815|0.9864|797 / 808|808|

其他伴奏各个有采音的乐段均改善，但主歌里仍有多余事件。鼓的片段成绩不能代替这个更弱的全曲结果；原流程召回 558/562 组但误检多，新模型只匹配 412 组，减少误检的同时也漏掉了原本检出的声音。钢琴是起音证据，不代表音尾或双押层数同样准确。

鼓分类分别报告严格 kick、snare、hi-hat，以及 side-stick、ride、tom 的诊断映射。作者词表把 MIDI 37 标为 Snare X-stick，因此会额外核对它与第 2/3 列的对应，保留原本严格 snare 结果。第 4 列含其他鼓音色，不能把它伪装成纯 hi-hat 真值，也不能按最高评分挑一个映射作为模型表现。

全曲严格类别 F1 分别为 kick 0.8281、snare 0.2152、hi-hat 0.1704。把 side-stick 与 snare 合并后，第 2/3 列对照为 0.7175；将 hi-hat、ride、tom 合并后，第 4 列仍只有 0.3431。它还没有学会用户这张谱的鼓音色与取舍，不能只报告合并起音的 0.7803。

另把冻结的 YourMT3 鼓事件作为局部分类器的附加证据，候选起音、频谱特征、拟合区间和校准区间全部保持原协议。8 个固定 GM 鼓类分别记录三个相对时间窗内是否出现起音，特征不读取作者拍位或书签。后段 kick/snare/第 4 列 F1 为 0.9516/0.9176/0.3037，原频谱分类器为 0.9555/0.9286/0.3814，整体退步，拒绝启用。新增模型证据并不会自动解决作者取舍与物理音色标签的差异。

### 起音改善不等于音尾可靠

保存的 token 经官方解码器重新解码，与原始音符列表逐项完全一致后，再追踪每个音尾的来源。全曲其他伴奏 1905 个模型音符中，1372 个端点有显式 note-off，499 个带强制分段截断记录，202 个与同音高重弹重合，另有 30 个固定 10ms 的鼓事件。这些标记可以重合，不相加当作总数。

强制截断来自分块交界处的持音状态不一致，不能当作乐器自然放音，更不能直接变成 LN 放手。即使有显式 note-off，也只是模型预测，尚不是音尾真值。新增审计保留逐音符来源供后续声部规划使用，不修改原始输出，也不自动连条。

全曲钢琴的 1221 个音高事件也包含 111 个带强制分段截断记录的音尾。Reference 钢琴全部是短键，因此不能用 0.9864 的起音组 F1 来证明这批音尾可用。

另外复用三组此前冻结的对照，不调整模型阈值：

|对照|YourMT3 结果|限制|
|---|---|---|
|40 秒已知复音合成音|音高起音 F1 0.6544，起止同时匹配 F1 0.5899；至少 2 秒音正确配对 18 个|起音只召回 71/130，仍有明显漏音|
|12 秒重复合成和弦|48 个已知音符全部漏检|没有错误长条是空输出造成，不能算音尾成功|
|另一段真实钢琴，谱面 5317787 前 40 秒|起音组匹配 114/117，F1 0.9194|现有深度路径为 0.9306；短键参考不能评价音尾|

决定：保留为独立乐器证据研究，不全局替换现有采音。需要继续解决不同音色的漏检、分块音尾和乐句层数选择；不能因为《樱花草》某个声部改善就宣称完成通用采音。

随后加入带物理起止标注的两首真实弦乐、六个独奏/混音输入，全部按事前固定的规则选择。起音与完整音长在六例中均优于现有检测，但大提琴漏音、混音类别错误和分块音尾仍未消除，详见[真实弦乐对照](instrument-transcription-benchmark.md)。这项补充支持继续研究该模型，不等同于完成 LN 编排。

### 从音高事件学习声部取舍与层数

新增轻量多分类实验，输入为冻结 YourMT3 的起音组、局部声轨频谱、音高/乐器类别分布、持续长度分布和音尾来源标记。按 30ms 聚合和弦起音，输出钢琴 0–2 层或其他伴奏 0–4 层；0 层表示作者未选择表达，不表示声音不存在。**没有把一个 MIDI pitch 机械转换成一个 note。**

拟合区间为 0–162340ms，层数偏置只在 162340–188286ms 校准，后段 188286–283840ms 单独报告。特征不包含作者 BPM、拍位、书签、歌曲绝对位置或谱面密度，不对预测吸附人工网格。其他伴奏的最优校准偏置落在事先固定搜索范围边缘，未根据后段分数扩大范围。

|后段声部|每组单点 F1|每组双押 F1|按音高数放键 F1|学习取舍/层数 F1|
|---|---:|---:|---:|---:|
|钢琴|0.8885|0.7483|0.8844|0.9198|
|其他伴奏|0.6214|0.6259|0.5386|0.6893|

钢琴预测 320 个物件，匹配作者 328 个中的 298 个；其他伴奏预测 198 个，匹配作者 243 个中的 152 个，仍有明显漏选。这里评价的是已检测起音上的作者层数选择，不是音色分类、LN 起止或完整成品。原始谱面没有参与后段特征或阈值选择，但同曲重复乐句仍存在相关性，模型保持研究用途。

### 跨歌曲层数检查：拒绝通用启用

将冻结的钢琴层数权重、偏置和 22.5ms 制谱提前量原样用于此前固定的《River Flows in You (Lorenzo de Luca Cover)》前 40 秒（谱面 5317787，另一位作者）。没有在这首歌上重新训练、校准或吸附网格。提取特征的公共函数先重现了《樱花草》全部已保存的层数预测，逐组时间、音符索引和层数完全相同。

另一首曲子有 175 个作者物件、117 组起音，其中 46 组双押、6 组三押。模型最多两层，预测 130 个物件、匹配 121 个，物件 F1 **0.7934**；直接按检测音高数限为两层为 **0.9080**，每组单点为 0.7785。模型只给了 11 组双押，漏选明显；三押真值保留在分母，未删去以提高分数。

因此同曲后段的 0.9198 不能作为通用层数模型的启用依据。这是不同作者的制谱取舍对照，不是唯一正确的音乐密度；同时也说明下一步需要结合段落、目标难度和用户选定声部学习取舍，不能直接套用单曲分类器。这张谱参加过另外的定轨先验训练，但没有参加本次层数分类器的拟合或校准；不把整个工程对此曲称为全新盲测。

### 音尾错窗复核：没有足够收益

另对先前固定的六组真实弦乐和三组控制音频运行半窗口错位推理，只允许用另一遍同音高、同乐器、起音一致的显式 note-off 替换被强制截断的音尾。实际结果未显示可靠的真实录音收益，**拒绝接入默认流程**。完整规则、逐例成绩与失败原因见[错窗复核](instrument-overlap-research.md)。这一结果也说明音尾的“显式预测”标签不能当成准确性保证。

## 检测草稿 → 实际编排

将冻结的声部预测真正串联到 Mapper：鼓使用频谱分类器的起音，钢琴和其他伴奏使用 YourMT3 起音及已训练的声部层数；不使用作者 Reference 的 HitObjects 组装输入。明确提供作者红线和四细分，按已知网格对齐，因此这仍不是自动 Timing 验收。军鼓暂时单押交替放在第 2/3 列，钢琴第 5/6 列、其他伴奏第 7–10 列；这是来源标记草稿，不是演奏定轨。全部物件先保留为短键，不把未验收的转录音尾当 LN。

输入全曲 2291 个物件，网格合并 29 处同列同时间候选，记录被合并的原始 ID，没有按人工真值删改。固定 215.853–227.853 秒，三个来源的起音组匹配分别为鼓 25/32、钢琴 45/45、其他 15/15；同起音物件数匹配为 39/60、47/53、25/36。给定正确 Timing 后的毫秒误差不表示盲采音精度；鼓漏选、其他伴奏层数仍差。

直接使用原先的首事件加权适配器时，九个推理窗口有八个从 column 或 hitsound 开始，输出残缺事件后停止，最终为空谱。输入解析和草稿激活日志均正常，不能把它当作音频没有声音。

随后从同一适配器继续训练 32 步，只将训练输入换成冻结的检测草稿，目标仍为作者成品。拟合音频范围 0–149367ms、后段验证范围 188286–283840ms，30 个训练窗口中 16 个冷启动、14 个带前文；验证 12 窗。源分类器的原有拟合/校准范围另见上文，同曲重复乐句相关性仍存在。44 次真实输入前缀比较全部逐 token 一致，22 个冷启动目标共 23416 tokens 通过完整事件语法检查。

在相同草稿、音频、Timing、难度、LN 条件与 seed 下，追加训练后输出恢复为 **171 个物件、43 个 LN**。匹配作者起音组 48/48、放手组 12/31、完整 LN 9/57，完整 LN F1 **0.1818**。仍有一处同轨重叠、9 条未闭合 LN 警告，不能启用默认权重。此前给作者草稿的 0.2626 使用不同输入，不能把二者当作同条件的模型优劣比较。

军鼓层数也做了单独拟合：冻结的 snare 起音候选上预测 0/1/2 个物件，阈值仅在中段校准。后段物件 F1 为单押 0.6667、始终双押 0.9231、学习层数 0.9161。学习结果没有超过简单对照，保持研究用途，没有偷偷替换上述已运行的草稿。

对这个新适配器再开启此前的事件状态约束，得到 141 个物件、41 个 LN，实际导出无同轨重叠，保留了全部 48 组作者起音。不过放手匹配下降为 11/31，完整 LN 匹配下降为 5/57，F1 0.1053；仍有 5 条片段末尾的未闭合警告。与这次未约束的相同输入结果相比，结构合法性改善、LN 表达退步，**仍不默认启用**。片段末尾的持条不完整还需更长上下文核对，不能与中段重复条头混为同一问题。

现有训练已经证明可以从检测草稿恢复非空生成，但并没有证明模型学会了可靠的 LN 规划。后续需要把“节奏锚点之间的编排手势”与“乐器物理持续时间”分开建模：作者成品中许多 LN 以其他声部起音作为放手点，不能仅靠延长转录音尾修复，也不能靠删掉不合法事件来制造成功。

## 本地重现
