# 多排键型先验研究协议

本研究检查四排窗口级键型偏好能否补足现有单排负例训练。它只在固定音符、
起止与 LN 长度下学习轨道分配，不选择采音、声部或 LN 时长，也不默认启用。

## 数据边界

- 从 `test-data/corpus-expanded/snapshot-verified` 读取已校验的 Ranked/Loved
  6–10K 谱，复用 `records_and_groups()` 的歌曲、谱包、音频哈希及别名连通组
  与 `split_for()` 划分；先分组再造窗口。
- 明确排除《樱花草》谱包 2644803、BeatmapID 5969639/5969640 所属歌曲组。
  Reference 与成品只作为固定的开发对照，不进入训练、验证或测试。
- 每谱最多抽 80 个连续起音排窗口，1–4 排右对齐；LN窗口和tap窗口各分配一半
  预算。每个歌曲组、键数最多保留 1,000 个窗口，多个难度共享预算。
- 预处理报告逐谱及按键数/切分汇总候选窗、抽样窗、负例搜索、失败和留存数量，
  同时报告LN/tap覆盖与窗口最大和弦尺寸。无足够可行负例的抽样窗会被丢弃，
  当前不补抽；因此窗口预算是上限，实际覆盖以报告为准。
- 正例是该窗口的作者轨道。每个正例生成两个可行负例，只扰动1–3排的轨道，
  保持原音符、起音和尾端，检查所有同轨占用约束。只改变左右镜像的负例视为
  等价而丢弃。模型不会用生成结果自我标注。
- 每图缓存同时保存诊断和 `FEATURE_NAMES` SHA256；配置还包含显式缓存版本。
  负例生成或抽样语义改变时必须提升缓存版本，不可继续复用旧窗口。
- 局部节拍特征忽略非有限、非正或超过 10,000ms 的红线周期；忽略后沿用
  前一条有效红线，没有有效红线时使用 500ms fallback。被忽略红线数逐谱和按
  键数/切分累计。该限制只保护研究窗口特征，不改写原谱或应用 Timing。
- 定时过滤规则属于特征生成语义；对应缓存版本为 `sequence-window-cache-v3`，
  不复用 v1/v2 的窗口缓存。
- 固定随机种子 `20261111`；训练使用 24 epochs、每轮 200 steps、batch 512、
  CPU算子线程2、跨算子线程1。按键数和LN/tap窗口均衡取样，验证集选轮次，
  测试集仅最终报告。

## 评价与决策

先报告每键数及LN/tap窗口的人类窗口排序准确率和loss。它衡量合法替代布局下
的局部排序，不能视作生成谱质量。后续若要接入beam search，必须独立检查相同
候选事件的整谱定轨、LN协调/放手/反键、负担、耗时和 `.osu` 回读。

《樱花草》冻结12个共同bookmark作为段落边界，同时检查Reference角色带宽
（1–4鼓、5–6钢琴、7–10其他）与成品10K的跨列LN/hybrid表达；不能把两张谱
合并成一个比例目标或声学真值。即使窗口排序有提升，也不单独据此启用默认；
还需要检查固定输入的具体片段、真实声轨和玩家实际试打。
