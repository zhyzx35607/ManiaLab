# 根据声音证据提出编排方案

从音频分析开始，先提出旋律与放手、均衡 Hybrid、密集多声部三个方向，再让用户选择并调整。方案解释哪些检测音支持它、局部密度上限及 LN 目标，绝不把建议值标成 osu! 星级。

语料的作用是提供键数与风格分布，以及固定时间下的轨道偏好。新曲的起音和 LN 尾端必须来自新曲检测。Ranked / Loved 的作者选择是参考，不是所有声音的完整转录标签。

## 学段落条件下的写法，而不是套用单曲模板

《童话》和《樱花草》是两个不同写法的例子，不是两套可硬编码的模板。用户给出的《童话》分段说明编排会随钢琴、人声、鼓、吉他进入和退出而变化；《樱花草》则说明同一首歌的主歌与副歌也可能采用不同的人声 LN 组合。目标是学习“看到本曲这一段的声音与上下文后，作者倾向怎样表达”，不是记住“主歌单条、副歌双条”或某个全曲 LN 比。

本地同作者谱面也说明全曲比例没有足够表达力：《童话》10K（`5848413.osu`）全谱 LN 比约 78.6%，用户描述的八段按现有起止时间切分后，各段约为 55.5%–100%；《樱花草》10K 成品（`finished.osu`）约 34.2%，Reference 约 8.5%。这不是质量排序，而是同一作者能按曲目、版本和创作目的切换表达密度的证据。

对冻结的《樱花草》Reference / 成品 10K，另按两图共同的 12 个书签划分为 13 段，生成逐段表达报告。分析入口为 `scripts/analyze_sakura_expression_profile.py`；机器报告保存在本地忽略目录 `test-data/sakura-benchmark/expression-profile-v2/report.json`。除开头 0–6664 毫秒仅有 7 个物件的引子外，成品各段 LN 比为 10.7%–52.3%，LN 中位时长为 0.5–2 拍：例如 188.286–215.853 秒段为 52.3%，峰值同时按住 10 轨；结尾 267.744–283.840 秒段降至 10.7%，LN 中位时长为 2 拍。Reference 与成品的逐段 LN 比也明显不同：6664–32610 毫秒 Reference 没有 LN，而成品为 62/171；97475–123421 毫秒 Reference 没有 LN，而成品为 56/164。Reference 的鼓/钢琴/其他列身份已由作者确认，成品 10K 只按键列统计，不猜测其音符对应的乐器。脚本会校验固定谱面 SHA256 与 BeatmapID；重新运行时须指定新 `--output` 路径以保留历史报告。

这些数值支持“表达随段落、密度和持续层互动变化”，不支持把这些时间段或比例硬编码成模板。报告是单曲谱面描述；成品谱的 LN 端点不构成声学音尾真值，也不能单独定义其他歌曲的正确写法。

可验证的目标分为四层：

1. **段落状态**：合并用户书签、参考谱的 Kiai 状态切换、明显配器变化、重复段落相似度、能量与音符活动变化，给出带置信度的边界。导入的书签和 Kiai 切换只是可编辑结构提示，不证明它们对应主歌、副歌或乐句；固定长度窗口也只作上下文，不当作语义标签。
2. **声部计划**：每段分别估计可听到的声部、主次、起音活动、持续层和强度变化。没有足够声学证据时标记未知；不能用“全曲某乐器通常重要”替代本段证据。
3. **乐句表达策略**：对候选事件组联合考虑 tap/LN、和弦规模、部分放手、交接、Hybrid、反键、重复动机和留白。LN 起止长度用拍长与乐句上下文表达，而不是单一毫秒阈值或固定全曲比例；输出多个可行策略及其依据。
4. **轨道布局**：把已经选定的起音、表达动作和放手时机一并交给可玩性约束，比较左右手负荷、放手拥挤、手指占用和重复句式。只优化固定 LN 端点的轨道排序无法替代这一步。

Ranked / Loved 谱可以教图形表达先验，例如段落条件下的 LN 长度分布、和弦/交接/放手组合及重复段落中的变化；它们不能单独说明这些选择对应哪条实际乐器，也不能证明延长到某个尾端有声音依据。训练样本因此应分别保存谱面动作和声学证据：`chart_end` 描述作者写到哪里，`evidence_end` 描述输入音轨支持到哪里。若未来允许风格性延长，应标为独立动作和来源，不伪装成真实音尾。

研究验证不能只看平均 LN 比或轨道排序分数。先按歌曲组划分 6–10K 数据，固定同一批音频候选，对照当前生成器、无风格先验和新策略；分别审查稀疏人声、密集鼓、持续贝斯/弦乐、声部交替、重复段落和结尾收束。报告按段落的 LN 比、拍长归一化尾长、和弦规模、放手顺序、占轨/放手负担及声音证据；最后仍需并排试听与实际试打。示例谱只用于定位策略差异，不能同时作为训练样本和泛化证明。

## 当前实际执行的流程

1. 保留原始起音、持续区间、检测强度、声部和有连续证据的人声乐句。
2. 按目标键数读取独立的语料统计。同一首歌的多个难度先在曲内汇总，歌曲组之间等权。短键、Hybrid 和 LN 为主的谱分别统计。
3. 依据本曲强度达到 0.35 的候选，提出全局和局部方案。采用方案后实际生成使用同一候选范围；原始采音不删除，清除方案可手动取舍弱音。当前分段使用约 15 秒分析窗口，不声称已经识别主歌、副歌或完整乐句。
4. 用户采用后，方案真正进入起音取舍、LN 选择和轨道搜索。之后调全局密度、LN 比例和协调滑块，也会相应调整局部建议。空白窗口不会被补出 LN 配额。
5. 在已确认拍线下选择音符并量化，使用 LN 容量与未来起音约束求解，再做连续轨道搜索。导出后重新解析文件，核验数量、起止、轨道与落线。
6. BPM、键数或采音证据改变时，旧本地方案失效，要求重新选择或清除计划。采用方案不会覆盖用户已确认的 Offset 和制谱提前量。

“旋律与放手”使用较低的语料密度分位，并参考 LN 为主的样本，避免被高速短键谱的平均密度推高。其低负担目标仍只是编排方向；低密度不保证释放容易，高密度也不保证音乐丰富。

当前缺口：`style.describe_chart` 提取的是全曲统计；`expression.propose_expression` 主要由全局 LN 参数和声部类别选择段内模式；`arrange.choose_holds` 只从已有、可信的持续音候选中选择 LN，保留候选音尾；普通表达层不会根据作者风格延长音尾。现有 v8 序列先验固定起音与 LN 端点，只研究轨道排序。因此程序还不能学会某一段选一组 LN、只延长其中一条，或安排与下一声部的错开放手。

当前大规模扩展语料有 7,907 张 6–10K `.osu` 谱面，但没有配套音频。另建的首批小型配对集从 7,902 张可用谱中选出 74 个歌曲组，成功取得 72 份对应原曲；它仍不是声部标注集：每份只有混音和作者谱，不能直接告诉模型某个 note 属于哪件乐器，也不能证明 LN 尾端有声学依据。覆盖尤其不足的是 10K LN-heavy（只有 2 个测试组、无训练或验证组）和 8K LN-heavy（没有样本），9K LN-heavy 也只有 3 个训练组。大语料适合学习作者画出的图形表达分布；小配对集可用于核对音频对齐、探索弱监督，但要训练段落声部角色与真实音尾，仍需补足有来源记录的声部/音尾证据，并保留每条候选与谱面动作的对应关系。

## 可以考虑的表达情况

下表是设计词汇和条件，不表示每项都已有独立学习模型。当前自动机会识别与局部定轨能覆盖其中一部分；跨乐段动机记忆、乐器主次识别和真正乐句级难度规划仍待验证。

| 声音或结构条件 | 可考虑的表达 | 必须检查的依据 |
|---|---|---|
| 同时起音、同时收尾的持续层 | LN 和弦 | 各层都持续，不能仅因和声相同就拉等长 |
| 分次进入、共同结束 | 递进入手、共同放手 | 只在检测尾端本来接近并量化到同尾时采用 |
| 同时开始、分次结束 | 阶梯释放 | 双手的放手顺序与间隔是否可读 |
| 起点、终点都错开 | LN 协调 | 同手相邻释放与按键是否过密 |
| 一条持续音内有另一声部短音 | 长按中的短键 / Hybrid | 短音确实存在；同手与分手是可选负担 |
| 多条持续层很少短音 | 进入与放手的层次 | 不靠新增短键填满空白 |
| 人声换音高但声音连续 | 跨音高人声长条候选 | 持续覆盖、呼吸缺口、重新发音与串音 |
| 人声停顿，伴奏仍延续 | 由伴奏承接持续层 | 不能把人声 LN 无依据地跨过停顿 |
| 同一音高重新发音 | 分开起音、重新进入 LN | 不被连续音高平滑成一根长条 |
| 同一声部节奏稳定重复 | 保持可辨认的布局动机 | 当前检测只能提示，跨乐段复现尚未完整实现 |
| 连续上行或下行 | 与旋律方向一致的轨道移动 | 同时和弦的多个音高不算连续旋律 |
| LN 结束后短正间隔再起 LN | 反键接续候选 | 空隙真实存在，不能填长间隙伪造 Inverse |
| LN 尾端附近有新短音 | 放手后短键、或分手接短键 | 放与按是两个动作，避免把同步事件重复计罚 |
| 短音之后进入持续层 | Shield 或分轨进入 | 保留短音起点与新 LN 的真实起止 |
| 相同持续层由不同声部交接 | 换手或轨道接续 | 不能仅因相邻时间就认作同一乐句 |
| 长音与快速装饰音并存 | 保留主持续层，选择装饰音 | 低密度方案需要舍弃部分装饰，仍保留主重音 |
| 密集琶音或多个同时音高 | 多声部、和弦或轮替 | 音高检测的谐波、跨声部分离重复要先排查 |
| 鼓密但旋律稀疏 | 节奏与 LN 的分层 | 鼓的衰减尾巴不能直接当可听的持续旋律 |
| 原曲稀疏、停顿多 | 留白、少量起音及清晰释放 | 不以曲风或“高难”目标要求程序凭空添音 |
| 段落逐渐增加声部 | 分段增加密度或同手配合 | 先有新增声音；当前窗口统计不是渐强语义识别 |
| 段落突然变薄 | 降低占轨、突出收尾 | 不能沿用前段的密度配额填空 |
| 乐句结束、余响仍在 | 按可辨结束组织放手 | 分离残留和混响容易把尾端拖长，需要试听 |
| 很短但清晰的持续音 | 短 LN | 用 BPM 和实际长度判断，不使用全曲固定 240ms 一刀切 |
| 长时间同时按住多轨 | 控制占轨与可用手指 | 物件数少也可能很难，需要释放与手指负担共同评估 |
| 变速、三连音、切分 | 在对应节奏网格检查起止 | 当前新谱仅单段 BPM；变速原谱只能严格保时重定轨 |
| 用户想强化反键或高难 | 增大对应偏好并对照候选 | 参数只控制现有声音的表达，不证明可玩性或音乐质量 |

## 从参考谱学到什么、没学到什么

小型轨道网络对“人工当前排”和“同历史下合法的替代排”打分。新增训练按键数与 LN 上下文均衡采样，加入不同放手顺序的合法候选，同曲多个难度共享限额，避免一个谱包支配学习。

标明 Inverse / 转换的谱可以进入 `layout_only` 参考组，贡献固定时间下的轨道几何；它们不进入默认持续长度校准。7+1 / IIDX 与 4+6K 属于不同手布局，仍不作为普通 8K 与 5+5 的 10K 训练样本。

没有配套音频、准确时间对齐和持续音标注，仅增加 `.osu` 数量无法教会模型听懂乐器音尾。本轮扩充解决的是风格覆盖、布局偏好和建议依据；采音、音乐性与玩家体验另行验证。
