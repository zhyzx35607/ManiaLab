# ADT_STR原始推理与语法对照：未通过

2026-11-10补充：[原float全曲与独立解码审计](drum-adt-str-research-2026-11-10.md)仍复现循环问题。核对本记录后撤回重复语法方案并终止未完成的MDB扩展，不将部分结果称为完整评价。

2026-11-09。按[事前协议](adt-str-protocol.md)运行作者默认setting-tau-0.8，严格加载官方权重并保留111个分块的原始tokens。源码、权重、配置与运行快照固定在本地。原输入为既有int16试听文件；其削波限制见[原PCM审计](raw-pcm-input-audit.md)。

原始全曲283.84秒的推理耗时3951.7秒。官方宽松解码后有1348个事件，去重前后差1965行；这些不是可验收的转录输出。独立按时间/自定义鼓类/力度三元组审计得到：

|问题|计数|
|---|---:|
|同时间同鼓类重复|2221|
|缺少EOS的块|11|
|不完整三元组的块|12|
|非法力度token|255|
|非法自定义鼓类token|2|
|超块时间token|252|
|时间倒退|1|

错误计数可重叠，不加总为音符数；后几项包含循环失步后的三元组审计，不能解释为同数目的独立声学错误。新版审计会检查没有EOS的残存内容，而旧运行审计在缺EOS时直接返回，因此新旧错误总数不同。原报告不改写，独立审计另存。

第4块的64-token诊断已经能看到同时间kick反复生成。把输入改为原float或逐块峰值归一化float，都没有解决该块循环；第5块三种输入均结束。不能把全部失败归于试听削波，也不能将推理时间长当复杂音乐分析的证据。

[事件语法对照](adt-str-grammar-protocol.md)只限制合法事件、不允许同刻重复，仍在第4/5块达到512-token上限，已明确失败，未补EOS。该次仅前四块原始token已保存；失败批在当时版本未保存，不虚构恢复。后续代码改为在token上限异常中保存失败批并记录哈希。

新版评分入口重新读取所有tokens，检查片段实际长度、重复、顺序、EOS后内容与独立解码一致性，不能信任旧报告的成功标志。该原始运行被明确判为不适合事件评分，没有据宽松解码的1348个事件报采音F1。上游固定100ms音尾也不能成为LN证据。

完整原始结果位于`test-data/sakura-benchmark/drums-adt-str-v1`，其中`runner-snapshot.py`是实际运行的旧代码，SHA256为`13652fc76795045318e7281fd9e9585420255ff1602f818ff785d933cbf7489c`。独立审计文件为`independent-token-audit.json`。语法失败保留在`drums-adt-str-grammar-v1`。本项未接入默认生成，也未发行权重。
