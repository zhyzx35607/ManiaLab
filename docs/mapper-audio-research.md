# Mapperatorinator 音频事件微调记录（2026-11-08，研究中）

本轮开始真正复用 Mapperatorinator V32 的音频编码器、tokenizer、OsuParser、MMRS 数据构造和 mania 解码器进行 LoRA。此前轨道先验、候选取舍模型不能替代这项训练。本轮未修改应用默认模型，也未发布新的 Release。初始实验已出现退步，不能称为交付质量改善。

应用接入处修复了一个对照失真：原模型输出不再自动经过定轨搜索，先保留模型生成的轨道。如果有同轨冲突，候选与界面如实标出，导出继续要求结构校验通过。用户仍可主动执行普通重新定轨；已确认 Timing 的量化行为保留并记录移动。这避免用后处理覆盖新模型学到的 LN 配合，也不把“成功生成候选”显示成“结构检查通过”。

## 用户要求与模型分工

目标是先有可信的音频时间与声部证据，再决定每段表现哪些声音、用短键或持续音表达，最后生成 6–10K 轨道与 LN 配合。Mapperatorinator 的训练标签是人工制谱事件，并非每个乐器的完整音符转录。将全谱标签直接配给独立人声或钢琴，会制造错误的声部标签；当前训练只配对原混音与原人工谱。

Nova 本地提取物中有公开分离算法与应用符号，但专用权重仍为 ENCM 加密。当前六声部采用公开 Demucs，不等同 Nova 私有模型。Torosu 的键型思想仍作为后续布局参考；它不能补足缺失的乐器起止真值。分段与逐声部表达策略已有界面，本轮尚未把独立声部、段落策略共同编码进 Mapperatorinator。

## 已完成的初始实验

在《有点甜》的 24–36 秒使用同一 10K、seed 42、BPM 210、Offset 93 和 LN 条件 55%，对原混音、人声、钢琴分别做真实推理。输出未经本项目量化、重新定轨或追加 LN 规则：

|输入|导出物件|LN|耗时|
|---|---:|---:|---:|
|原混音|87|60|385 秒|
|分离人声|27|24|242 秒|
|分离钢琴|78|0|444 秒|

这仅证明不同输入影响生成，不能当作乐器转录准确率。混音有 LN 起止不完整警告；钢琴在同样 LN 条件下输出全短键。直接把声部送进现有模型，并未达到可靠的声部持续表达。

初始 LoRA 更新了 442,368 个参数，64 步实际覆盖 32 份训练谱，每谱固定抽取两个全曲窗口。15 首验证的 teacher-forced 时间事件 NLL 从 3.709 降至 3.440、轨道 NLL 从 2.082 降至 1.916；LN 起点类型准确率反而从 65.11% 降至 63.39%。LN 尾类型约 94% 的准确率只是“此处是尾类型 token”，**不等于放手时间准确率**。

在验证谱 `4606010`（10K `lit(var)`）24–36 秒，自由生成使用同一音源、完整人工 TimingPoints、原谱 LN 比例与难度、seed 42；参考 HitObjects 和 Bookmarks 没有传给生成模型。短片段六个起音组均匹配人工谱；完整 LN 区间的一对一 F1 从 0.667 下降至 0.625，且两份输出均出现一个不完整 LN 警告。这是对一种人工创作的相似度，不是音乐质量的充分评价。初始权重不启用。

## 训练窗口修正

初始约 8 秒独立窗口缺少跨窗状态；检查 150 个缓存窗口时，发现 54 个含没有前文起点的 LN 尾，另有一个达到目标 token 长度上限。因此新训练采用原 V32 约 16.376 秒音频窗口，其中约 8.192 秒为真实前文，约 8.184 秒为当前目标；前文事件可见但不计算误差。前文覆盖超过原模型 8 秒 sustain token 间隔，让跨窗长条有可见的持续状态。

通过独立适配类调用上游解析与序列构造，未改动上游目录。所有目标时间窗口相邻、不重叠，段尾使用明确的排他时间边界，避免切片遗漏最后一帧的事件。超过完整 token 容量的窗口明确计数并跳过，不把被截断事件当作完整标签。每首仍采用全曲确定性抽样。

完整缓存检查：150 个新窗口包含 1,645 个被监督的 LN 尾，全部能在解码输入中找到同轨起点或 sustain 状态。候选窗口中 67 个超过 token 容量被跳过；所有 75 份谱均仍取得两个样本。跳过高密度窗口可能改变训练分布，需要继续关注。额外使用上游真实解析器验证了跨多窗的 25 秒 LN 与窗口边界音符：4 个 LN 头、4 个尾、2 个短键均恰好监督一次，未出现无前文的目标 LN 尾。

新评价单独统计 LN 起点时间、放手时间、短键时间，使用另一个验证歌曲的音频编码作为反事实对照。更低的 teacher-forced loss 以及更高的人工谱相似度仍不能代替自由生成、试听和试打。

修正后的实验完成 256 步，实际覆盖全部 60 份训练谱：10K 128 步，6/7/8/9K 各 32 步；Hybrid 82 步、LN 98 步、短键 76 步。优化与末次验证合计约 1,956 秒，不含此前音频编码和基线验证。仍只更新 442,368 个解码器适配器参数，音频编码器冻结。

|相同验证窗的指标|原模型|微调后|
|---|---:|---:|
|LN 起点时间 token 精确预测|64.15%|67.86%|
|LN 放手时间 token 精确预测|54.55%|58.33%|
|轨道 token 精确预测|54.83%|56.73%|
|LN 放手时间误差 ≤30ms|85.31%|85.73%|
|短键类型 token 精确预测|94.23%|92.87%|

这些是给定真实前文后的预测，时间 token 间隔为 10ms。与初始短窗实验的输入、抽样窗口不同，不能跨表比较绝对分数。允许 30ms 误差后的放手收益很小，短键类型还有退步，不能描述为采音已解决。

## 本地运行

需已安装固定原模型的独立 Python 环境。配对数据、模型与歌曲放在忽略目录 `test-data`，不会随仓库或 Release 分发。

```powershell
# 准备脚本要求已核验的配对清单和固定谱面快照；不会自动伪造或下载缺失音源。
.venv\Scripts\python.exe scripts/prepare_mapper_training.py --ffmpeg <ffmpeg.exe>

test-data\mapperatorinator\venv\Scripts\python.exe scripts/train_mapper_audio.py --steps 256 --threads 2 --output test-data/mapper-training/lora-context
test-data\mapperatorinator\venv\Scripts\python.exe scripts/evaluate_mapper_audio.py --run test-data/mapper-training/lora-context
.venv\Scripts\python.exe scripts/probe_mapper_adapter.py --adapter test-data/mapper-training/lora-context/adapter --output test-data/mapper-adapter-probe/context-litvar
```

探针生成原始 `.osu`、哈希、警告、匹配报告，以及本地 `review.html` 和原音乐/起止提示 WAV。页面不需要 osu!，三份谱共用音频时钟；点击跳转、切换提示均已做浏览器检查。研究报告应同时保留改善和退步，不用谱面数量、LN 比例或训练步数代替效果验收。
